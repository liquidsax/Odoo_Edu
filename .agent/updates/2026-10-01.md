## 错题记录改造：关联练习册 / 辣椒难度 / 记录时刻 + 门户自加（PR #6）

分支 `feature/mistake-workbook-portal`，提交 `8ac25d8`，**PR #6 已由管理员合并**（合并点 `c5a379d`）。

### 需求与共同确认的设计取向

维护者要「点开学生 → 记录不会的题」，并明确：

- **来源 = 练习册**（五年模拟三年高考、一数课后习题……），要能单独管理练习册；
- **不记题目内容**（不通过平台做题，只记"错了哪道题"）——去掉原富文本；
- **留时间戳**（什么时候记录的）；
- 学生门户也要能看到这些题；
- 追加：**Excel 式增量录入**、**辣椒难度 2~5 🌶**、**学生可自助添加自己的错题**。

据此定稿：来源由写死的"课内/考试/其他"改为关联练习册；发生日期（可手填）与记录时刻（系统自动）并存；题目富文本换成可选"错因/备注"。

### 数据模型

| 模型 | 变化 |
|---|---|
| `tutoring.workbook`（练习册，**新增**） | `name`（必填）、`note`、`active`；`mistake_ids` + 计算字段 `mistake_count`。`models/tutoring_workbook.py` |
| `tutoring.mistake`（错题，**重构**） | 删 `source`(Selection)、`description`(Html)；加 `workbook_id`(M2o，**必填**)、`page`(页码)、`question_no`(题号)、`difficulty`(Selection 2~5，标签为 🌶×n)、`note`(错因/备注，可选)、`recorded_at_text`(compute，把 `create_date` 按用户时区格式化) |

辣椒难度用 **Selection + emoji 标签**：库里只存 `'2'~'5'`，标签 `🌶🌶…` 只在 UI 渲染，后台可编辑网格、表单、门户三处通用，**零自定义 JS**。

### 界面

- **后台**：顶栏「数学辅导」菜单由 学生/知识点 扩为 **学生 / 错题 / 练习册 / 知识点**；
  - 错题列表与学生表单「错题记录」页签均为 `editable="bottom"` **可编辑网格**——逐行增量录入，练习册/教学内容可即输即建；

- **门户**：新增 `/my/learning/mistakes`（列表，按状态筛选、按记录时刻/发生日期排序、分页）与 `/my/learning/mistakes/<id>`（详情）；学习总览「最近错题」卡改为显示 练习册+页码题号+辣椒+状态，加「+ 添加」「查看全部错题 →」；

## 晚间：年级叫法改为初一~高三（含键值补零迁移）

分支 `feature/grade-naming`，在独立 worktree `E:\Odoo-wt\grade-naming` 完成——与维护者本机主工作区

### 需求

维护者指出知识点页（`action-377`）的年级用「七年级/八年级/九年级」，而日常叫法是「初一」这类，
要求改过来；确认范围时追加**同时提供高一/高二/高三**。

### 第一版实现踩到的真问题：Selection 键值的字符串排序

只改显示名、键值仍用 `'7'~'12'` 的版本，在一次性库里实测出错：

```
ORDER_MODEL [('10','T10_1'), ('11',…), ('12',…), ('7',…), ('8',…), ('9',…)]
ORDER_GROUP ['10','11','12','7','8','9']
```

Selection 在库里存**字符串**，知识点模型的 `_order = 'grade, name'` 与搜索视图的「按年级分组」
（知识点 action 默认 `search_default_group_grade`）都按字符串比较，于是 `'10' < '7'`——
**高一/高二/高三排在初一之前**，正是用户每天看到的那个页面。Odoo 19 的 `read_group` 对
Selection 字段也**不按选项定义顺序**排，按值排。

### 定稿

| 文件 | 改动 |
|---|---|
| `models/tutoring_knowledge.py` | 抽出模块级常量 `GRADE_SELECTION`，键值**补零**为 `07~12`，标签 初一/初二/初三/高一/高二/高三；附注释说明补零是为排序 |
| `models/tutoring_student.py` | 复用 `GRADE_SELECTION`（原先两处各写一份，易漂移），`default='07'` |
| `migrations/19.0.1.2.0/pre-migrate.py`（新增） | 对 `tutoring_student`、`tutoring_knowledge_point` 执行 `lpad(grade,2,'0') WHERE grade IN ('7','8','9')`，可重复运行 |
| `__manifest__.py` | 版本 `19.0.1.1.0 → 19.0.1.2.0`（触发迁移） |
| `views/tutoring_views.xml` | 知识点 action 帮助文案「例如七年级的…」→「例如初一的…」 |
| `dev/seed_data.py` / `dev/seed_knowledge.py` | 灌数据用的键值同步为 `'07'` / `'08'` |

### 方法论补充

- 新增/调整 Selection 选项时**先想清楚键值的字符串序**：凡按业务顺序展示（分组、`_order`）的

### 追加：辣椒组件"看着正常其实没挂上"的根因

统一升级后浏览器里难度列仍是默认渲染。诊断链：DOM 上有 `o_field_chili`/`o_chili_cell` 类名
（这两个类名只来自 arch 的 `widget="chili"`，**不代表组件已注册**），但单元格里是
`<span raw-value="3">🌶🌶🌶</span>`（默认 Selection 渲染）；控制台给出
`Missing widget: chili for field of type selection` 与 "modules … have unmet dependencies"。

根因：`chili_field.js` 里 `import { standardFieldProps } from "../standard_field_props"` 照抄了核心
文件的**相对路径**。`odoo/tools/js_transpiler.py` 按文件所属模块改写路径，于是它变成
`@tutoring_center/standard_field_props`——本模块没有这个文件，整个组件模块加载失败。改为绝对别名
`@web/views/fields/standard_field_props` 即修复。

资产包没跟着变的原因：编译产物缓存在 `ir.attachment` 的 `web.assets_backend.min.js`/`.min.css` 两条记录里，
只在收到 assets 失效信号时重建；`button_immediate_upgrade()`（就地升级）会重载 registry 但不触发该信号，
所以包还是旧的。删掉这两条 attachment 后下次请求按磁盘新代码重新生成——curl 两次字节数
`6309251 → 6309253`，包内依赖由 `@tutoring_center/standard_field_props` 变为
`@web/views/fields/standard_field_props`，无需停服。

**要点**：默认 Selection 的标签本身就是 🌶 emoji，组件没生效时列表看起来完全正常——
"看到辣椒"不等于"组件挂上了"，必须核对自定义类名是否出现在 DOM 里。

## 练习册改造：教材 PDF 入库 + 页中页滚动阅读（feature/workbook-file-reader）

分支 `feature/workbook-file-reader`（切自 `origin/main` = `eef4ef6`，已含 PR #9/#10）。
**本轮只交代码：未升级模块、未重启服务、未做浏览器验收**（维护者要求：有同事在同一实例并发开发，
先不碰服务）。manifest 版本直接跳到 `19.0.1.4.0`——`19.0.1.3.0` 已被并发分支
`feature/knowledge-tree` 占用（陷阱 13 的同类风险）。

### 需求（维护者看 `/odoo/action-379` 提出）

① 现在点单元格就地改库，太容易误触——改数值或加行必须先点「修改」；② 单击行改成打开**页中页**；
③ 新建的书（如《五年高考三年模拟》）在页中页里从本机上传 PDF，传完这本书就在**本机 PostgreSQL 里**；
④ 传完就能在页中页里**用滚轮看**；⑤ 传错了还能在同一处换文件。选项式提问后定：
纯原生双弹窗（不写 OWL 组件）、`bytea` 存库、支持多文件（上册/下册/答案）、门户学生也能读，
错题本轮不挂文件。

### 数据模型

| 模型 | 变化 |
|---|---|
| `tutoring.workbook.file`（**新增**，`models/tutoring_workbook_file.py`） | `workbook_id`(M2o, required, cascade)、`name`(required, default `新教材`)、`content`(Binary **`attachment=False`**)、`filename`；`_compute_display_name` → `书名 · 卷名`；`_viewer_action()`(@api.model) + `action_open_viewer()` |
| `tutoring.workbook`（改） | 加 `file_ids` / `file_count`；加 `_form_dialog()` 与四个动作：`action_open_reader`（只读页中页，context 带 `footer: False`）、`action_open_edit`（修改台）、`action_new_workbook`（控制栏新建）、`action_new_file`（上传教材） |

`attachment=False` 是关键选择：Odoo 19 里 Binary 默认 `attachment=True`，正文进 `ir.attachment`，
而 `ir.attachment.location` 默认值是 `file` → **字节其实躺在磁盘 filestore**，库里只有元数据。
改成 `attachment=False` 后 `column_type` 变成 `('bytea','bytea')`，PDF 直接是本表一列，
`pg_dump` 即全量备份，这才符合"传完书就在 postgresql 里"。代价：库体积随教材涨、读整本进内存
（服务默认 `limit_memory_soft=2048MB`/`hard=2560MB`，单本百 MB 级仍安全）。

正文不会被列表页拖出来：Binary 默认 `prefetch=False`，所以 `file_count`、文件清单、门户列表页都只读行，
不取 `content`。**任何"按 content 过滤/显示大小"的写法都会把整本 PDF 读进内存**（`bin_size` 对
非 attachment 列仍是先全量读再 `human_size`），要显示体积得另存一个整数字段。

### 界面（全原生，零自定义 JS；仅 1 个 CSS 文件）

- **列表**：去掉 `editable="bottom"`，改 `<list type="object" action="action_open_reader" create="false">`
  ——19 原生支持 `list` 的 `action`/`type`（`list_arch_parser.js` + `list_renderer.onCellClicked` →
  `openRecord`，base/rng/list_view.rng 已声明这两个属性），行点击调 Python 方法返回弹窗动作；
  常驻「新建练习册」用 `<header><button display="always" icon="fa-plus">`（陷阱 12 的写法，方法不带 `@api.model`）；
  原先 `active` 的 `boolean_toggle` 从列表移除（点一下即归档＝另一种误触），归档改到修改台里操作。
- **页中页①阅读台**（`view_tutoring_workbook_form_reader`）：字段全 `readonly="1"`，
  header 有「上传教材」+「修改」，动作 context 里 `footer: False` 关掉保存/放弃；
  教材子列表同样用行点击 → `action_open_viewer`。
- **页中页②修改台**（`view_tutoring_workbook_form_edit`，也用于新建）：名称/备注/`active` 可改，
  `file_ids` 用 `editable="bottom"` 网格，`content` 列走原生 `list.binary` 就地上传（`options` 限 `.pdf`），
  另有「看」按钮——**可编辑网格里单击单元格是进编辑态，行 `action` 不会触发**，所以这里必须显式按钮。
- **页中页③阅读器**（`view_tutoring_workbook_file_form`）：`widget="pdf_viewer"`，
  无文件→"Upload your file"，有文件→✏️重新上传（换错文件）/下载/🗑；正文用
  `/web/static/lib/pdfjs/web/viewer.html?file=/web/content/…`，滚轮翻页；
  上传后组件先用 `URL.createObjectURL` 直接渲染，**点「保存」才写进 bytea 列**。
  `name` 用 `readonly="id"`：新建时可题名、已存在只读（题名去修改台改）。
- **弹窗尺寸/开关是 context 键**：`dialog_size`（`extra-large|large|medium|small`）、`footer`——
  `action_service.js` 里 `DIALOG_SIZES[action.context.dialog_size]` 与
  `actionDialogProps.footer = action.context.footer ?? …`，核心 `account_peppol` 已在用。
  另：`dialog` 在 action service 里是**单个槽位**，弹窗中再开弹窗是**替换**不是叠层，
  且旧 dialog 的 `onClose` 会传给新的（列表 `openRecord` 绑了 `root.load()`），
  所以"改完关闭 → 列表自动刷新"是白捡的；代价是阅读台被修改台替换掉，要看新文件得再单击一次行。
- **iframe 高度**：核心 `fields.scss` 给 `.o_field_widget.o_field_pdf_viewer .o_pdfview_iframe` 写死
  450px，`static/src/fields/workbook_pdf_viewer.css` 把它抬到 `74vh`。选择器**只写自己在 arch 上给的
  `o_workbook_pdf_viewer`**（`field.js` 会把 arch 的 `class` 并到字段根节点）再加一个 `iframe` 元素名提高
  优先级——**不要**依赖 `o_field_pdf_viewer`：那来自 widget 的 `additionalClasses`，而 `pdf_viewer` 组件
  并没有声明它（`field.js` 里是 `[o_field_${this.type}]`，未必等于 widget 名），赌错了就变成"CSS 写了但没生效"
  的静默失败（同陷阱 14 的辣椒教训）。该目录已被 manifest 的
  `web.assets_backend: ['tutoring_center/static/src/fields/**/*']` 通配收走，无需改资产清单。

### 门户（学生只读教材）

- 路由：`/my/learning/workbooks`（按本人错题出处归集的书名列表）、`/my/learning/workbooks/<id>`
  （该书文件清单）、`/my/learning/workbook-files/<id>`（pdf.js iframe 阅读页，与后台同一查看器）；
  `/my` 首页加「教材」卡片（计数 `tutoring_workbook_count`），错题详情页在 `file_count` 时加
  「看《某书》的教材 →」入口；面包屑沿用 `page_name == 'tutoring_workbooks'`。
- 权限：`tutoring.workbook.file` 教师 `1,1,1,1`、门户 `1,0,0,0`；记录规则 `rule_workbook_file_portal`
  与既有 `rule_workbook_portal` 同款 `[(1,'=',1)]`（教辅资料按共享物对待，学生本来就能在错题表单里看到全部书名）。
  **若要收紧成"只看自己错题涉及的书"，改这条规则的 domain 即可**，控制器与模板不用动。
- 出流校验链：`/web/content/<model>/<id>/<field>` → `ir.binary._find_record` →
  非 attachment 走 `record.check_access("read")` → `Stream.from_binary_field`，mimetype 由文件头猜成
  `application/pdf`、`download=False` → `Content-Disposition: inline`，所以能内嵌显示。
  注意 `/web/content` 响应带 `Content-Security-Policy: default-src 'none'`，别指望在 iframe 里跑 PDF 内嵌脚本。
- 上传体积上限：客户端 `session.max_file_upload_size`（参数 `web.max_file_upload_size`，默认 **128MB**）
  拦一次，整份 base64 走一次 JSON-RPC 写入；`FileUploader` 的 `acceptedFileExtensions` 只限 `.pdf`。

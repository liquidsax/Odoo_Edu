# 2026-10-03 更新：错题页体验改造（PR #20）

> 分支 `feature/mistake-page-ux`，模块版本 `19.0.1.7.0 → 19.0.1.8.0`，等待管理员审查合并。

## 改了什么

错题页（`action_tutoring_mistake`）从数据库式只读表格改造为教师友好的页面：

1. **卡片看板为默认视图**（`view_tutoring_mistake_kanban`）：按学生分栏的错题卡片
   （练习册 + P页·题号、错因两行截断、发生日期、辣椒 widget、教学内容标签），
   栏头带难度分布进度条（`<progressbar>` 子元素）；整卡点击走 `action_open_reader`
   弹只读详情（core kanban 根节点 `action`/`type` 属性原生支持，关弹窗自动刷新）；
   拖拽/改组/栏级新建全关（`records_draggable="false"` 等）。视图切换器：看板/列表/图表。
2. **顶部统计概览条**（列表与看板共用）：`共 N 条 / 本月新增 / 高难度 / 未填错因`，
   取数走新模型方法 `tutoring.mistake.summary_stats()`（`@api.model`，返回 4 个计数）；
   自定义 `js_class`（`tutoring_mistake_kanban` / `tutoring_mistake_list`）继承
   `KanbanController`/`ListController`，模板 `t-inherit="web.KanbanView"/"web.ListView"`
   在 `<t t-component="props.Renderer">` 前插 banner；组件订阅 `model.bus` 的 `"update"`
   事件自动刷新（检索变化和弹窗记账后的重载都会触发）。除总数外三个数字可点击
   切换对应筛选：`env.searchModel.getSearchItems()` 按名字找 search item，
   普通过滤器 `toggleSearchItem(id)`，日期筛选 `toggleDateFilter(id, "month")`；
   激活态读 `searchModel.query`。代码在 `static/src/mistake_stats/`。
3. **图表页签**：`view_tutoring_mistake_graph`（柱状、按月计数），`view_mode` 变为
   `kanban,list,graph,form`。
4. **列表/检索**：`decoration-danger="difficulty in ['4','5']"` 行标红；
   搜索视图加原生 `<filter date="date" name="filter_date"/>`（自带今天/本周/本月…）
   和「基础难度(2~3🌶)」；动作 help 文案重写成两句教师视角引导。
5. kanban 视图补了自己的 `<header>`（快速记录/新建错题）——header 按钮是**每个视图
   自己 arch 里解析的**，列表里写了看板里不会出现。

## 验收记录

  signaling reload 不重导 .py，必须重启）→ shell 里 `button_immediate_upgrade()` 落库。
- 真机浏览器验收（真实点击）：卡片点击弹详情、高难度/本月 chip 筛选（facet 同步 +
  chip 激活态）、栏头进度条、图表切换、快速记录弹窗、列表红行——全部通过。
- 一次性新库 `zz_ux_check -i tutoring_center` 安装通过（陷阱 9），验完已删库；
  临时验收账号 `qa_ux` 已删。

## 新陷阱（追加到 Top 17 之后）

18. **Odoo 19 kanban 模板名固定**：卡片模板必须 `t-name="card"`（菜单 `menu`），
    自定义名字报 `Missing 'card' template`；arch 里**禁止用 `__comp__`**（服务端
    校验直接拒绝）。想在卡片模板里知道当前分组字段：自定义 `KanbanRecord` 子类覆写
    `renderingContext` 塞入 `groupByField`，再通过自定义 `KanbanRenderer` 的
    `static components` 替换 `KanbanRecord`，视图注册时给 `js_class` 那条
    `registry.category("views")` 记录同时带上 `Renderer`。
19. **kanban 进度条是独立的 `<progressbar field="..." colors='...'/>` 子元素**，
    不是 field 节点的 `progress` 属性（后者静默不生效）。
20. **就地升级后资产 404 / 浏览器白屏的排查路径**：先看页面引用的 bundle URL 哈希
    变没变（哈希 = 文件清单+mtime 的 sha，未变说明文件清单没进包）；删
    `web.assets_web.min.js/.css` 两条 `ir.attachment` 后**浏览器可能仍被 service
    worker 旧缓存坑**（先 `navigator.serviceWorker.getRegistrations()` 注销 +
    `caches.delete` 再刷新）；`/web/assets/...` 404 而 shell 里
    `_get_asset_bundle(...).js()` 能建出来时，多半是服务进程的 ormcache 资产
    路径还旧——重启服务一次干净。
21. **工作树可能被外部切回 main**（多 agent 并发 / 用户手动）：提交前
    `git branch --show-current` 确认分支；这次提交落在 main 上，用
    `git branch -f feature/... <commit>` + `git branch -f main <origin-main>` 平移修复。

## 遗留

- 「发生日期」chip 二次点击取消"本月"后，若之前手动在日期下拉里选过年份，
  年份 facet 会残留（原生日期筛选的多 generator 行为，影响很小，未处理）。
- KPI 数字是全局统计（不随当前筛选变），这是设计决定：chip 本身就是筛选入口。

# 2026-10-03 晚：更正「部署副本」这套说法 + 本地分支/凭据清理

## 判形态的实测（`E:\Odoo` 到底是啥）

维护者明确定调：**`E:\Odoo` 不是副本，也不是"需要切分支来部署"的检出点，它就是最重要的那份源码，一切从这里开始。**
今天逐项复核，与这个说法一致：

- `Get-Service` → `odoo-server-19.0` 与 `postgresql-x64-18` 均 Running；
- 磁盘只有 `server/ python/ nssm/ odoo.conf.example`，**没有** `odoo19/`、`E:\Odoo\odoo.conf`、`pgsql/`、
  `pgdata/`、`start-odoo.bat`（即 10-01 记的那套"开发模式"在本机不成立）；
- 业务库 `OdooForDB`；`addons_path` 第二项 `E:\Odoo\server\addons` 落在仓库主工作树里
  （`git worktree list` 第一项就是 `E:/Odoo`）。

**作废并改写**：handoff §2 末尾的"已重做成开发模式"注记、§4.1「先同步部署副本再谈升级」、
§一规则 7 与 MULTI_AGENT 第一/二/三节里所有"手抄副本 / `cp -a` 覆盖 / `diff --strip-trailing-cr` 比副本"的步骤。
新写法是：改文件即改到服务读的那一份，`git pull` 之后只差一次 `-u`（Python 变更再加一次重启），
不存在同步动作；代价是**共享工作树上别人未提交的 WIP 会被你一次重启一起加载**，所以占用声明里要多写一句
`git status` 是否干净。`updates/2026-10-01.md` 里那两节按"当日所见"保留原文不改，以本节与 handoff 为准。

# 2026-10-03 晚（第二批）：改名 R3ynA 学习平台 + 错因字典 + 门户错题页重做

> 分支 `feature/r3yna-brand-and-mistake-review`（从 `main` d37f976 起），模块版本 `19.0.1.9.0 → 19.0.1.10.0`。
> 需求来自维护者自己的使用体验：网站挂着"数学辅导"的名，实际还要记 leetcode 好题、看过的科教书；
> 门户错题页在数据量涨起来之后没法用；错题缺知识点与错因，复习时聚不起来。

## 改了什么

**1. 品牌改名（只改显示，模型不动）**
`__manifest__.py` 名称/摘要/描述、后台应用菜单 `menu_tutoring_root`（数学辅导 → **R3ynA 学习**）、
权限类别与组说明、首页大标题与四张卡片（把已退出界面的"作业跟踪"换成"错题记录""教材阅读"）、
门户 `/my` 卡片文案（去掉"错题订正"这个已经不存在的说法）。
库里那份 `website.name=数学辅导学习平台` / `res_company.name=数学辅导中心` 由新增的
`data/branding_data.xml` + `models/website.py::_apply_tutoring_branding` 统一盖过来，
顶栏 logo（`static/img/logo.svg`）与浏览器图标（`static/img/favicon.png`，Pillow 画的 R3 块）一起换，
后台应用磁贴补了 `static/description/icon.png`。页脚那串旧名是历史上 `dev/branding2.py` 直接写进
`website.footer_custom` 的库内容，模块没有它的 XML 副本，所以用
`ir_ui_view._apply_tutoring_footer_branding` 按旧串就地替换（没跑过那个脚本的库是空操作）。

**2. 错因字典 + 知识点关联**
新模型 `tutoring.mistake.cause`（名称/归类/怎么理解/排序/有效 + `unique(name)`），
`data/mistake_cause_data.xml` 预置 13 条、按"概念→审题→运算→策略→习惯→其它"排好、`noupdate=1`。
`tutoring.mistake` 加 `cause_id`、`cause_category`（存下来的 related，才能按归类分组）、
`point_id`（知识点）、`knowledge_grades`/`student_grade`（related，只为给视图当域）。
`note` 改名"补充说明"。后台：列表/看板卡片/两个页中页/速记向导/学生页签的可编辑网格都补了这两列，
搜索视图加"未标错因""未选知识点"与按知识点/错因/归类分组。
知识点挑选域 `[('grade','in', knowledge_grades)]` 复用学生上现成的 `knowledge_grades`；
门户 POST 里服务端再校一次年级（下拉看不到 ≠ 塞不进来）。
顺手修了 `tutoring_mistake_quickadd.py` 用 `ValidationError` 却没 import 的真 bug（超 100 题号会 `NameError`）。

**3. 门户错题页重做 + 隐式复习队列**
取数从"全量 `search()` + Python `sorted()` + `page_size=10` 硬编码 + 4 次 `search_count`"
换成 `domain`+`order`（白名单字典，键值不再进 SQL）+`limit/offset`，药丸计数三次 `read_group` 出。
新增：搜索（题号/页码/说明/书名/知识点/错因/教学内容）、分组（按知识点/错因/月份，
点标题下钻、条件胶囊可摘）、每页 10/20/50、卡片网格（正面只放知识点+难度+错因+出处+一句摘要）、
详情页就地补一句想法（新路由 `POST /my/learning/mistakes/<id>/note`）。
复习机制：`last_review_at`/`review_count`/`next_review_at` 三字段**不进任何视图**，
`GET /my/learning/mistakes/<id>` 里 `touch_review()` 按 1→3→7→15→30→60 天推到期日，
默认 `sortby=review` 让"到期最早的排最前"。存量行的 `next_review_at` 由
`_migration_backfill_review` 回填成 `create_date`（不回填的话 PostgreSQL 把 NULL 排在升序末尾，老错题永久沉底）。

# 2026-10-12 工作记录：错题页做成"同页可切的试用版本"（批次① `19.0.1.32.0` → 批次④ `19.0.1.34.1`）

维护者的原话是：现在的错题是**记录式**的（只记 书 + P页 + 题号，不要求拍照、不抄题目），
这个模式好用的地方正是"零重复操作"；但光有记录没有内容，容易变成**死记录**——题多了分不清主次，
下次翻开不知道干什么，最后就不想打开这个页面。所以这一批的目标不是"哪个方案对"，
而是**让他自己轮流用几天，凭手感说哪个让他还想打开**。

他当场给了四个想法：B 站式大封面（大图画）、卡片按重要性上色 + 一个类 Excel 页、队列式首屏、
抖音式整屏刷题流。并明确否掉"一个一个做版本"：**所有版本要同时挂在同一个页面上随时切**。

## 一、这一批做了什么（批次①，四件，全不要图）

`/my/mistakes` 顶部新增「试用版本」分段控件，`?lab=wall|queue|grid` 三版并存，
**共用同一份取数、同一套筛选/排序/搜索/下钻**，差别只在首屏怎么排：

| 版本 | lab | 内容 |
|---|---|---|
| 卡片墙 | `wall` | 原来那一版，不动；分组下拉只在这一版出现 |
| 今日队列 | `queue` | 首屏只摆"该翻出来的"，每张卡把理由写在明面上，其余整段折起来 |
| 表格 | `grid` | 一行一道题，日期/页/题号/难度/错因/知识点/补充说明就地改，一次存整屏 |

- 卡片按**轻重分四档上色**（`hot/due/hard/cool`）：到期越久 × 难度越高越红，左边一道色条 + 极浅底色。
  同一句话同时挂在 `title` 上（桌面悬停、手机长按都能读），**颜色不是唯一通道**。
  不建新字段、不进后台视图、不构成"订正状态"那种要人维护的东西。
- 到期判定抽成 `tutoring.mistake._due_domain(now)`，队列首屏与卡片配色共用一份口径；
  首屏与"其余"按同一个条件**对半分**（到期 ↔ 未到期），不是筛选，所以不重也不漏。
- 表格那条写入口 `POST /my/mistakes/grid`：逐行 `search()` 过记录规则，**够不着的行整行忽略**
  （回执 `saved=N` 里就不计它）；认不出的值**跳过那一格而不是清空**；某行的知识点/错因
  不在"当前范围那份档案"的可选项里时只给看不给下拉——否则一保存就把别人的值抹了。
- 标签刻意中性（不写"推荐""新版"）：否则测出来的是标签自己的说服力。
  单人轮流试，所以**没做**"记住每个人习惯用哪个"的字段，也没做反馈埋点（他自己收反馈）。

## 三、探针抓到的两条硬事实

1. **`fields.Datetime.now()` 拿到的值、以及写进库里再读出来的值，微秒都是 0**。
   我给"剩余天数"写的 `int(秒 // 86400) + 1`（本意"不满一天算一天"），在**正好整倍数那天**
   会多加一格：写 +5 天，页面说"6 天后再看"。实测 `剩余秒数 = 432000.000` → `//86400 = 5.0` → `+1 = 6`。
   改成 `math.ceil(...)` 才对（`ceil(5.0) = 5`，`ceil(4.99) = 5`）。逾期那一侧用 `.days`（下取整）不用改，
   因为截断把存储值挪早了，`(now - due).days` 只会等于或大于真实值。
2. **带 `tz='Asia/Shanghai'` 写入 Datetime 再读出，值纹丝不动**（库里列、缓存读回、失效重读三者一致）。
   也就是说 `touch_review()` 那套"UTC now + timedelta"不会被用户时区挪走，排期机制本身是干净的。
   这条以前没人验过，属于"对了但没人证明它对"。

## 四、新陷阱 71~75

- **71** Datetime 的微秒在这条链路上会被抹平成整秒：凡"两个时间点相减再换算成天"的展示文案，
  向上取整要用 `math.ceil`，`floor + 1` 只在"非整倍数"时才对，整倍数那天恰好多一天。
- **72** 门户/网站页是**服务端 Python QWeb**，不是 OWL 的 JS QWeb：模板里可以写列表推导
  （本仓库早就在用 `[k for k in url_args if k != 'search']`）、`x in <set>`、`'a_%d' % id`；
  `t-call` 的片段读得到调用方 `t-set` 出来的变量，所以一个模板能服务多个版本而不必传参。
- **73** **一次性库建出来的一瞬间，正在跑的 8069 服务就会给它建 registry 并占着连接**
  （`pg_stat_activity` 里 `application_name=odoo-9128` 同一个进程连着 OdooForDB 和新库），
  于是 `DROP DATABASE` 报 "is being accessed by other users"。删一次性库要排在 `stop odoo` 之后，
  别在服务活着的时候踢它的连接。
- **74** 判"一次性库是否真的清干净"要**同时看 `pg_database` 和 `data_dir/filestore/`**：
  库早删了，filestore 里还留着 13 个孤儿目录（`zz_*_check`、`qa_mistake_page_196` 等）。
- **75** 控制器方法里用 `_()` 取标签，在 `odoo-bin shell` 里**调不动**——`Controller.env` 是只读 property，
  `odoo.tools.translate._get_uid` 顺着帧找 `self.env` 会拿到 `None` 并抛 `AttributeError`。
  要测"有哪几把键、标签中不中性"，就把模块里的 `_` 临时换成恒等函数；别为此去伪造 request。

## 七、三条封面各是怎么实现的

| 版 | 图从哪来 | 花了什么 |
|---|---|---|
| `coverpdf` | 后端 `/my/learning/mistakes/<id>/page.pdf` 吐**出处那一页**的单页 PDF，前端用 **Odoo 自带的 pdf.js** 在 canvas 上画成 JPEG 盖上去 | 零 token、零新依赖、不装任何东西 |
| `covercss` | 不出图，纯 CSS 把 出处 / 知识点 / 摘要 / 难度 撑成一张海报 | 零 |
| `coverai` | `models/mistake_cover.py` 用 **Pillow** 把已有的 `ai_summary`/`ai_question_text` 排成 PNG，按内容哈希缓存在 `ai_cover` 上 | 零 token（文字是错题摘要那批早就生成的） |
| `feed` | 一屏一道，封面走 `auto`（原页 → 位图 → 文字依次退让） | — |

- 关键前提都是**实测过的**，不是推的：本机 `python/Lib/site-packages` 里只有 PyPDF2 / pdfminer / Pillow，
  **没有任何 PDF 光栅化能力**（`pdftoppm`/`mutool`/`gswin64c`/ImageMagick 全查过，都不在）；
  而 `web/assets_frontend` 打包了 `web/static/src/core/**`，所以门户页能 `import { loadPDFJSAssets } from
  "@web/core/utils/pdfjs"`——`mail` 模块里那份 `generatePdfThumbnail()` 就是同一套做法的现成样板。
- 文字封面永远垫在底下，图加载成功才淡入盖上去；**任何一张失败只坏那一张**，并把原因写在角上。
  封面版最怕"整屏空白还什么都不说"。
- 位图里刻意不画 emoji（雅黑里 🌶 会出方框），难度写成"难度 4/5"；正文按 56/48/40/34 四档字号
  从大到小试，取第一档塞得进剩余高度的——只有一两句时不该留半张空白。
- 三条取图/写排期的口都按当前用户把关：别人的题一律 404；`page.pdf` 与 `cover.png` 回包带
  `X-Content-Type-Options: nosniff`（同源内联不能松，知识库那轮的教训）。
- "放过"按钮走的是现成 `touch_review()`，**没有新造状态字段**。

   提交仍走浏览器自己的 multipart，所以没跑 JS 的浏览器照样能记题（少一份重复实现，也少一条"JS 挂了就不能用"）。
4. **封面整条改路**：撤掉今天早些时候那套 Pillow 位图（`mistake_cover.py` 重写、
   `ai_cover`/`ai_cover_key` 字段与 `cover.png` 路由删除），换成
   **AI 只报"配方"，图由我们渲染**：
   - 素材表定死在 `models/mistake_cover.py`：**8 个背景色板 id + 12 个图案 id**（图案是内联 SVG 描边图形，

     `{"covers":[{"id":…,"bg":"ink","motifs":["ellipse","axes"],"headline":"≤14字概括","sub":"…","badge":"P13·第5题"}]}`，
     **不许出颜色值、不许出 SVG/HTML/CSS**；色板与图案清单由 Python 表注入 prompt，加素材不用改文案；
   - 回来一律过 `clean()` 白名单：认不出的 bg/图案丢掉、文字按长度截断；

## 十二、新陷阱 81~86

- **81** `tutoring.workbook._locate_page()` 开头就 `self.ensure_one()`。
  **练习册一旦可以空着**，所有走它的计算字段（`page_pdf`、`can_ai_summary`、`cover_*`）
  都会拿空集去 ensure_one → `Expected singleton: tutoring.workbook()` → 列表页当场 500。
  放宽任何"必填"之前，先顺着这类"假定自己一定被单条调用"的方法补空集退路。
- **82** 计算字段返回 dict 让调用方按键取值时，**坏输入路径必须返回同一个形状**。
  `_cover_plan()` 原本在 JSON 解析失败时直接 `return {}`，于是 `plan['headline']` KeyError；
  正确做法是坏输入也走一遍 `clean({})`（它保证五个键都在），调用方才可以不用 `.get()` 铺满地。
- **83** `deepseek_settings(env)` 返回的键是 **`key` / `model` / `url`**，不是 `api_key` / `base_url`。
  照名字猜会在第一次调用就 KeyError 500——抄现成调用方（`tutoring_mistake_ai._call`）比猜快。
- **84** 列表页**以前根本不读 URL 上的 `?error=`**：`_mistake_page_values(kwargs, form, error)` 的
  `error` 只由直接渲染传，重定向带回的参数被丢掉。任何"处理失败 → 303 回列表页并带原因"的新路由
  都会**静默把提示吞掉**（表现是"点了没反应"）。现在 `error` 会回落到 `kwargs['error']`。
- **85** 验收脚本的**执行顺序本身会咬人**：批次③的删除测试排在封面转义检查之前，
  导致转义断言永远看到 0 次命中，而手工探针同一时刻是 1 次——数据被脚本自己改了。
  破坏性断言要么排在最后，要么每段前重建数据。
- **86** 从 bash heredoc 喂给 Windows Python 的中文脚本要 `PYTHONUTF8=1`，
  否则按控制台代码页（cp936）解码，中文常量静默变成乱码，
  症状是 `str.index`/`startswith` 报 `ValueError`/`StopIteration`，而文件里明明有那一行。
  跨行改这些 md（CRLF）也一样：要么单行锚点，要么显式按 `newline=''` 读写。

另外三条红灯是**断言自己写错了**，产品没问题，全部改掉并留了注释：

- "换日子会丢范围"：它渲染时压根没给 `scope`，而回顾版没有分页链接，页面上自然不出现

  改成 `limit=50` 验"在不在集合里"，不验"排在第几页"。
- 反向那条"归档后不在第一页"是**假通过**（在第二页也算通过），同样改成 `limit=50`。

## 十六、新陷阱 87~90

- **87** `_read_group` 按日期分组时，`order` 里必须写**分组项的原名**：`date:day desc`。
  写 `'date desc'` 会被当成一个不存在的聚合/分组项直接 `ValueError`；
  粒度 `date:day` 也不能省（否则 `Granularity not set on a date(time) field`）。
- **88** 一次性库没删干净不只是难看：**两个库 + 空 `dbfilter`** 会让 Odoo 对无会话请求

- **89** 验收脚本里"打开详情页"这个动作本身会推后排期（`touch_review`）。
  所以"放回视野"这类断言必须按**在不在集合里**验，不能按"在第几页"验——
  否则既会假失败，也会在反向断言上假通过。
- **90** 子 agent 跑满轮次停机时留下的 `dev/zz_*_out.txt` 是**中途旧产物**，不能当现状：

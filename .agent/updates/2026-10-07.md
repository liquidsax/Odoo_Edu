## 一、这一批做了什么

### 云端（`server/addons/tutoring_center`，`19.0.1.19.0`）

- **五张表**（`models/tutoring_time.py`，一个新文件装完）：
  `tutoring.time.task` / `.session` / `.pool.item` 三张业务表 + `.device`（哪台机器写的）
  + `.sync`（每次同步的流水：方向、结果、新增/更新/删除/冲突/被拒计数、耗时、来源 IP）。
- 每行业务数据带 `client_id`——**由产生它的那一端生成**的稳定标识，云端不自造主键，
  所以同一件事从多台机器重复上报只会落一行（`unique(user_id, client_id)` / `unique(task_id, client_id)`）。
- **删除是墓碑而不是真删**：载荷里的 `deleted` 落到原生 `active=False`。用 `active` 而不是自造
  `deleted` 布尔，是为了让门户、`search_count`、`read_group` 这些读路径**自动**跳过墓碑行；
  代价是同步自己查行必须显式带 `active_test=False`，这条收在一个 `_lookup()` 里（见陷阱 56）。
- **乐观锁用服务器发的 `rev`，不比较客户端时间戳**：多机的本地时钟互相不可信。
  内容一致时判 `noop`——这是为"服务端写成功但响应被网络吃掉"准备的，见下面第五节的实测。
- `total_seconds` 云端按区间重算，只累**已结束**区间，与 Do1ng 的 `totalMillis` 口径一致；
  精度上 Do1ng 落盘只到秒，所以两边最多差"每段区间 1 秒"，写在模型 docstring 里没有含糊过去。
- 时区：客户端上报带偏移的 ISO（`2026-10-07T07:30:00+08:00`），云端存 UTC，
  并额外存一列 `local_date`（= UTC + 该行自己的偏移）供按天分组。
  不这么做的话 `read_group('start_at:day')` 按 UTC 切，东八区早上 7 点那段会被算进前一天。
- **三条机器接口**（`controllers/time_sync.py`）：
  - `GET /tutoring/time/ping`（`auth='public'`）——探活，不回答库名/模块版本；
  - `POST /tutoring/time/login`（`auth='none'`, `readonly=False`）——自己实现而不复用
    `/web/session/authenticate`，只为了客户端不必填库名（云机 `list_db=False`，
    拿不到 `/web/database/list`）；单库时核心会 monodb 自动解析（`http.py:_get_session_and_dbname`），
    解析不出来才回 503；
  - `POST /tutoring/time/sync`（`auth='public'` + 自判空会话、`csrf=False` + 要求自定义头
    `X-Do1ng-Sync`）。**为什么不用 `auth='user'`**：核心对 `type='http'` 路由的会话过期处理是
    **302 到 `/web/login`**（`http.py:2516`），桌面客户端跟着跳就会把登录页 HTML 当同步结果解析。
- **门户 `/my/time`**（批次①是"能确认数据真上来了"的最小页）：概览四卡（今日 / 本周 / 进行中 / 任务）
  + 同步状态条（最近一次 + 可折叠流水表）+ 状态药丸带计数 + 搜索 + 排序 + 每页 + 任务卡片墙 + 分页；
  没数据时是一页三步接入说明。全部沿用 `portal.portal_layout`、`card border-0 shadow-sm`、
  Bootstrap 5 与 `o_time_*` 命名，**零第三方依赖**；CSS 在 `static/src/time_portal/`，
  注册进 `web.assets_frontend`（陷阱 29：实际打包在 `assets_frontend_lazy` 里，验收要抓资产包确认）。
- 顶栏第 5 项「时间账本」（seq 40）+ `/my` 首页入口卡（`config_card=True`，
  一条没同步时也看得见，否则用户不知道要去桌面端登录）；两者都靠 `group_ids`
  让匿名访客看不到（陷阱 28）。
- 隐私与知识库同强度：五张表全挂 `[('user_id','=',user.id)]` 记录规则（内部 + 门户两组），
  老师之间互不见；`admin` 走 `base.group_system` 不受规则限制，需要代查用它。

### Do1ng 侧（`D:\WorkSpaceD\CodeMountains\Do1ng`，分支 `feature/cloud-sync`）

- 数据格式：`Session` 与 `PoolItem` 各加 `String id`（`model/Ids.java`，12 位 hex），
  构造函数里就生成，`TaskStore.sanitize()` 给旧数据回填并**当场写回磁盘**
  （不写回的话下次启动又是一批新 id，同步会把同一件事看成"删一条加一条"）。
  `PoolItem` 原来那句"刻意不带 id"的注释按新前提改了——有了同步之后那个理由不再成立。
- `net/OdooClient.java`：JDK17 自带 `java.net.http`，**没加任何新依赖**；
  手工搬 `session_id` cookie（不用 CookieManager，它默认拒收非 Secure cookie）；
  `Redirect.NEVER`；错误归成 10 类（NETWORK / TIMEOUT / TLS / UNAUTHORIZED / BAD_CREDENTIALS /
  THROTTLED / MFA_REQUIRED / REJECTED / SERVER / BAD_RESPONSE）；网络类与 5xx 退避重试 3 次
  （500ms 起指数 + 抖动），4xx 一律不重试。可选代理（`proxyHost/proxyPort`）。
- `net/Secrets.java`：DPAPI（`CryptProtectData`，CurrentUser 范围）经 PowerShell 调用，
  **零新依赖**；明文用子进程环境变量传递，不放命令行参数（命令行在进程列表里是明文可见的）。
- `sync/SyncState.java`：`data/sync.json`（与 `tasks.json` 分文件，被 `.gitignore` 的 `data/` 挡住），
  存服务器地址、账号、DPAPI 密文、设备号、间隔、最近结果，以及每行的 `{rev, hash, parent}`。
- `sync/SyncService.java`：**用内容哈希判脏，而不是给每个改动点埋脏标记**——
  `MainView` 里就有 16 处 `store.save()`，靠人工埋点必漏；哈希不一致才算脏，
  新改动路径不需要知道同步存在，忘了也没后果。删除同理：登记过而本地找不到的键就是墓碑，
  所以 `TaskStore.delete()` 一行没改。不变量："行在 `tasks.json` 里但 `sync.json` 没登记 ⇒ 一律当脏"，
  两次原子写之间崩溃的后果是**多传一次**（云端幂等 upsert 兜住），而不是少传一次。
- 触发：手动（标题栏「☁ 同步」+ 托盘 Sync Now）/ 改动后 30 秒 debounce（`refreshAll()` 一处挂钩）/
  心跳每 60 秒查一次"到点 && 有脏行" / 退出前最多等 4 秒收尾。全在一条自己的守护线程上，不占 FX 线程。
- UI：`ui/SyncDialog.java`（地址、账号、密码、记住密码、自动同步、状态行）+
  标题栏那颗按钮的文字就是状态（`☁ 3` / `☁!` / `☁ …`），细节在 tooltip；
  托盘两项一律英文（AWT PopupMenu 缺中文字形会渲染成方块，那条既有坑）。

## 二、同步协议（将来批次③要扩的地方）

请求：

```json
{"client": {"device_key": "…", "device_name": "…", "platform": "…", "client_version": "…"},
 "utc_offset_minutes": 480,
 "changes": {"tasks": [{"client_id": "…", "title": "…", "status": "ACTIVE",
                        "created": "2026-10-01T09:00:00+08:00", "interrupted_count": 2,
                        "updated_at": "…", "rev": 1, "deleted": false}],
             "sessions": [{"client_id": "…", "task_client_id": "…", "start": "…",
                           "end": null, "notes": ["…"], "rev": 0, "deleted": false}],
             "pool":     [{"client_id": "…", "task_client_id": "…", "text": "…",
                           "created": "…", "done_at": null, "rev": 0, "deleted": false}]}}
```

响应：`{ok, error, protocol, server_time, stats{created,updated,deleted,conflict,noop,rejected},
revs{"task:<id>": 3, …}, actions{"task:<id>": "updated"|"noop"|"conflict"|"deleted"|…},
rejected[], rejected_total, device_key, sync_id, duration_ms}`。

- `rev` 是客户端上次看到的服务器版本号；不匹配且内容确实不同 → `conflict`，**服务端不写库**，
  只把当前 `rev` 回给客户端。客户端于是保持"脏"，下一轮带着正确 `rev` 重推 → 收敛。
  一次冲突最多让改动晚一轮上云，两端都不丢。
- `actions` 是**逐行**的：只有聚合计数分不开"这行成了 / 冲突了 / 被拒了"，
  而客户端的记账必须分清（成了记 rev；冲突换 rev 但保持脏；被拒原样留着）。
- 墓碑只需要 `{client_id, rev, deleted: true}`（子行再加 `task_client_id`）：
  服务端对 `deleted` 的行**跳过正文校验**，并且父任务不在同一批时会回查数据库
  （否则"任务先删、区间后删"这条路会把子行永远拒在门外）。
- 批次③要加的：`pull`（服务端把 `write_date > 游标` 的行连同墓碑回给客户端）、
  字段级合并与冲突副本、网页端可写。

## 五、新陷阱 51~58（50 已被 2026-10-06 的"同义字段并存"用掉，这批从 51 起）

51. **`fields.Json` 把空容器存成 NULL**：`convert_to_cache` 里是 `if not value: return None`，
    读回来是 `False`。所以"`notes=[]`"与库里"空"永远判不相等 → 每轮同步都白涨一个 rev、
    流水里全是假的 `updated`。逐字段比对（幂等判定）之前必须把 `None/False/[]/{}/''` 归一。
52. **`_read_group` 对 date/datetime 分组必须显式给粒度**：`groupby=['local_date']` 直接
    `ValueError: Granularity not set on a date(time) field`（`odoo/orm/models.py:2095`），
    要写 `['local_date:day']`；而且回来的键可能是 `datetime`，当字典键用之前要摊成 `date`。
53. **stored 与非 stored 计算字段不能共用一个 compute 方法**：混写会得到两条 registry 警告
    （inconsistent `compute_sudo` / inconsistent `store`，后者明说"读非存量那个会连带重算并更新存量列"）。
    拆成两个方法，即使逻辑重复。
54. **`models.Constraint` 的消息不能在类体里直接 `_('…')`**：类体在**导入期**求值，那时没有语言
    上下文，全新库安装会刷 `no translation language detected`，而且这条消息**永远不会**按访问者语言
    翻译。`ConstraintMessageType = str | Callable[[Environment, Diagnostics], str]`
    （`odoo/orm/table_objects.py:16`，取值在 `get_error_message` :60），所以正确写法是
    `lambda env, diag: _('…')`。本模块既有 6 处约束都是老写法，没在这条分支里顺手改。
55. **`/web/dataset/call_kw` 会把 `args` 展开一层**：服务端是 `method(recs, *args)`
    （`odoo/service/model.py:97`），所以 domain 要走 **kwargs**，`search_read`/`search_count`
    传位置参数会把 domain 拆散成 `['url','=','/my/time']` 报 `Domain() invalid item`。
    只有**非 `@api.model`** 的方法（`read`/`write`）才该把 ids 放在 `args[0]`。陷阱 12 的同族。
56. **墓碑表用原生 `active` 的代价**：所有读路径自动过滤是好事，但同步查行必须
    `with_context(active_test=False)`，忘了就是"查不到墓碑 → 重新 create → 撞唯一约束"。
    把这一处收进一个 `_lookup()`，别散在三个调用点。
57. **Gson 反射的是"这个对象的所有实例字段"**：把 `Gson` 或 `Path` 当实例字段，序列化该对象时
    Gson 会试图序列化它们自己，一路撞到 `ThreadLocal` / `sun.nio.fs.WindowsPath` 抛
    `InaccessibleObjectException`（JPMS 不允许 opens）。基础设施字段一律 `static` 或 `transient`。
58. **PowerShell 的标准输出走系统 OEM 代码页（本机 cp936）**，Java 按 UTF-8 解 →
    任何非 ASCII 内容都会静默变乱码。DPAPI 探针实测：ASCII 口令往返正常，
    中文/变音符号/emoji **全部往返不一致**，表现就是"密码明明对，服务端却说不对"。
    子进程回传一律用 base64（纯 ASCII），解码在 Java 侧做。另外别让明文上命令行——任务管理器里看得见。

（另两条与本文相关但不属于 Odoo：不同模型的空记录集不能 `|`，会
`TypeError: inconsistent models`；以及本机到 `edu.r3yna.site` 的 TLS 握手实测 6 次只成 2 次，
直连和走 7897 代理都一样——"网络抖动"在这条链路上不是假设，是默认情况，所以客户端以本地文件为队列、
服务端以 `noop` 认重推，比任何"重试次数调参"都重要。）

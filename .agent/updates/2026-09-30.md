## 白天：网站新增「函数图像」绘图页

分支 `feature/website-function-plot`，提交 `53df6d5`（已 rebase 到 `e4d1fba` 后推送，PR 待开）。

### 交付内容

- 新公开页面 `/tools/function-plot`（`controllers/tools.py`，`auth='public'`），挂网站顶栏**第三位**（`website.menu` seq=30，位于 首页 / 学习平台 之后）。
- 主入口是**按类型填参数**：圆 / 椭圆 / 双曲线 / 抛物线 / 直线 / 二次函数 / 反比例 / 三角函数，点开弹层照题目填数即可；原手写方程框收进折叠的「自己输入方程（高级）」。
- 椭圆与双曲线各有两种填法：**分母式**（`x²/5+y²=1` 填 5 和 1）与**系数式**（照抄题目，`x²-4y²=4` 填 1、-4、4）。系数式是为避免教师为凑「右边为 1」心算而加（来自维护者的实际反馈）；参数不合法时预览处红字提示且不入图。
- `static/src/function_plot.js`（约 1600 行）+ `function_plot.css`，**零第三方依赖**（Chart.js 只能画统计图，画不出椭圆/双曲线）：
  - 解析：归一化（全角括号/等号、`²³`、`π`）→ 分词（连写字母拆分、隐式乘法）→ 调度场算法 → RPN → 闭包编译（不用 `eval`，避免 CSP 与注入问题）；
  - 判别与绘制：数值差分判断能否解出 y —— 能则显式采样、按跳变断开断点；不能（圆/椭圆/双曲线、`x²=±2py` 以外者）走隐式 marching squares，鞍点按中心值决定连接；
  - 两轴等比例（圆必须正圆）、1-2-5 自适应网格、滚轮以光标为锚点缩放、拖动平移、双击重置、悬停十字线读数——曲线画在主 canvas，十字线与读数画在叠加 canvas，避免每帧重算；
  - 全屏用 CSS 覆盖层（`100dvh` 兼容手机动态工具栏），同时尽力调用原生 Fullscreen API 并兜住 Promise 拒绝；
  - 弹层预览与曲线图例按数学写法渲染（`prettyEquation()`：`^n`→上标、`pi`→π、`log`→lg、去多余括号、`π·x`→`πx`），**先转义再替换**，注入的只有 `<sup>`。

### 本次抓到的三个真 bug（均已修）

1. **双曲线「焦点在 y 轴」两个分母用反**，与字段标签矛盾 → 会画出错误的双曲线（Node 用例发现）；
2. **正弦按周期换算时拼出 `pi/2x`**，被解析器读作 `pi/(2x)` → 图像错误；改为非纯数字一律补 `*`（`pi/2*x`）；
3. **画布内按钮点不动**：拖动处理对 `pointerdown` 调 `preventDefault()`，按规范会抑制浏览器合成的 `mousedown`/`mouseup`/`click`，导致「全屏查看」「重置视图」对真实鼠标点击毫无反应，`dblclick` 同被抑制（双击重置失效）。修法：命中 `button/a/input/label/弹层` 时直接放行；双击重置改为按 pointerdown 间隔（300ms）自行判定。

### 验证记录

- Node 用例 40+ 条：解析优先级（`2x^2`、`-x^2`、`2^-1`）、显式/隐式/竖直线判别、8 种类型的方程拼装与关键点代入、非法参数、渲染字符串、HTML 转义。
- 浏览器像素级实测：
  - `x^2/4+y^2/9=1` → 4.05 × 5.99 单位（真值 4×6）；`x^2+y^2=4` → 4.01 × 4.05（正圆，等比例成立）；
  - `x^2-4y^2=4` → 顶点精确落在 ±2，`|x|<1.9` 区间**零墨迹**（两支不连线，不会把渐近线当曲线画出来）；
  - `y=1/x` → 坐标轴两列零墨迹，两支断开；
  - 滚轮缩放 1.595×（理论 1.568）、拖动位移与指针一致、悬停读数正常；
  - 全屏：画布后备尺寸 454×487 → 531×785（= 视口 × dpr），退出后复原。

### 流程与工具结论（对后续开发很重要）

- **`static/src` 下的前端 JS/CSS 改动，刷新页面无效**，必须 `-u tutoring_center` 升级重建资产包（或启动加 `--dev=assets`）。已写入 `ONBOARDING.md` 热重载表与 handoff 第四节。
- 自动化验证的两个坑：
  1. Qoder 内置浏览器面板处于后台（`visibilityState=hidden`）时，**驱动点击不会向页面投递任何鼠标事件**，`requestAnimationFrame` 不触发、`setTimeout` 被节流到 ≥1s —— 此时"点击无效"之类的结论一律不成立；
  2. 脚本里用 `element.click()` 合成事件会绕过 `pointerdown → click` 链路，**掩盖上面第 3 个 bug**。交互控件必须真实点击验收。
- 用隐藏页里也能跑的方式验证：与重绘无关的探针（读 `defaultPrevented`、读视图状态换算出的读数、`getBoundingClientRect`）优先于"看像素/看截图"。

## 傍晚：全新库安装实测 —— 修掉两个"只有维护者的库能装"的隐藏依赖

维护者提出疑问：仓库只跟踪 `tutoring_center`，新机器配不起来怎么办。核查后确认**源码不入库不是问题，
但模块里埋着两个未声明的跨模块依赖，任何全新库首次安装都会失败**。

### 核查结论

- 仓库跟踪 50 个文件：`server/addons/tutoring_center`(25) + `.agent/` + `dev/` + `docker-compose.yml` + README/docs；
  `.gitignore` 明确排除 `/server/*`（只放行 `tutoring_center`）、`/python/`、`/nssm/`、`/backup/`、`odoo.conf`、`*.log`。
- **Odoo 本体源码零改动**：`server/odoo/` 下 5.2 万个文件 mtime 全为 `2026-09-21 11~12`（装机时刻），
  09-22 之后有变化的只有 `tutoring_center` 自己的文件；源码树里只有 `server/.gitignore`（陷阱 7）与
  `server/odoo.conf`（含密码、不入库）两处本机痕迹。⇒ ONBOARDING A2 那句 `git clone -b 19.0` 不会丢任何项目代码。

### 实测过程（一次性库，不碰 `OdooForDB`）

按 ONBOARDING A5 原命令 `-i tutoring_center --without-demo=all --load-language=zh_CN --stop-after-init` 建库：

1. 第一次失败：`AssertionError: The ID "contacts.action_contacts" refers to an uninstalled module`
   → `ParseError: partner_views.xml:47`；`website` 的依赖链里没有 `contacts`（只 dep base+mail），
   维护者的库装着 contacts 所以从未暴露。
2. 补 `depends` 后再建库，前进到下一处失败：`The ID "project.portal_my_home" refers to an uninstalled module`
   → `portal_templates.xml:17`。这是"关掉项目门户卡片"的清理性写法，project 本不该成为依赖
   （新库里根本没有 project，那张卡片也就不存在）。

### 修法

| 文件 | 改动 |
|---|---|
| `__manifest__.py` | `depends` 补 `'contacts'`——模块确实覆写了联系人应用的动作视图，属于真实依赖 |
| `models/ir_ui_view.py`（新增） | `VIEWS_TO_DISABLE = ['project.portal_my_home']` + `_apply_tutoring_view_cleanup()`，用 `env.ref(..., raise_if_not_found=False)` 容错停用 |
| `views/portal_templates.xml` | 删掉写死的 `<record id="project.portal_my_home">`，留注释说明为何走函数 |
| `views/menus_cleanup.xml` | 增调 `<function model="ir.ui.view" name="_apply_tutoring_view_cleanup"/>`（与既有菜单清理同一模式） |
| `models/__init__.py` | 导入 `ir_ui_view` |

### 验证

- 全新库 `edu_fresh_ok2`：`-i tutoring_center` 单模块安装**通过**，67 个模块加载、日志 0 CRITICAL / 0 ParseError；
- 临时实例（端口 8169，`--http-port/--gevent-port` 避开服务）冒烟：`/` 200 且含"数学辅导 · 学习数据平台"、
  `/tools/function-plot` 200 且 `data-plot-type` / `tutoring_plot` 等 DOM 齐全、顶栏含 `/my/learning` 与 `/tools/function-plot`；
- 资产包实测：`web.assets_frontend_lazy.min.js` 命中 `prettyEquation`×3 与 `tutoring_plot`×8，`web.assets_frontend.min.css` 含绘图样式
  （即全新库不需要额外 `-u` 就有正确的前端包）；
- 验证用一次性库与临时日志（`edu_freshcheck` / `edu_fresh_ok` / `edu_fresh_ok2` 及其 filestore、`dev/fresh_*.log`）
  已全部删除，本机只剩业务库 `OdooForDB`。删前需停一次 Odoo——`db_name` 为空时服务会预加载所有库，
  带着连接是删不掉的。

### 方法论（后续开发必须遵守）

- **每次改完 `tutoring_center` 都要用一次性新库跑一次 `-i tutoring_center`**：维护者的库是"全模块都装着"的状态，
  永远不会暴露未声明依赖；`--stop-after-init` 建库只需 20~40 秒，成本极低。
- 跨模块引用的三种正确姿势：真依赖 → 写进 `depends`；纯清理/装饰 → 容错 `<function>`；
  纯本机状态 → 留在 `dev/` 脚本里并在 ONBOARDING 写明是可选步骤。

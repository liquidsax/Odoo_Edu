# 2026-10-09 · 函数图像页「智能画图」

> 需求：在公开页 `/tools/function-plot` 上用自然语言描述图像，DeepSeek 只回方程，
> 再交给现有画布。分支 `feature/plot-ai-draw`，版本 `19.0.1.22.0`。
> **没碰共享服务和 `OdooForDB`，也没上云。**

## 设计

- 新模型 `tutoring.plot.ai.call` 记每次调用（发起人、自然日、状态、token、截断后的原文）。
  记录规则只看得到自己的。门户和内部用户都能建，不能改、不能删，状态流转走 `sudo`。
- 页面仍是 `auth='public'`。匿名只看到「登录后使用」，按钮展开的是登录链接，
  接口是 `auth='user'`。公开用户在模型里再挡一次 `AccessError`。
- 方程回到浏览器后调用现有 `addCurve(expr, {label, params})`。`params` 只播种这条式子里
  真出现的字母，当滑块初值；`label` 用 `textContent` 挂一枚徽标。离心率 / 渐近线仍只在
  「按类型添加」那条路上算，智能画图不从模型带回这些结构（模型会编）。
- 服务端另有一份与 `function_plot.js` 对齐的分词器（`models/plot_expr.py`），只判断肯不肯收，
  **不求值**。对不上的式子整条丢掉。`dev/zz_plot_ai_unit.py` 会拿同一批式子去对前端 `buildModel`。

## 额度与 token

- 每人每天 **10** 次，按发起人时区的自然日，`create()` 里对 `res.users` 行 `FOR UPDATE` 再数。
- 描述：去控制符后不能空，最长 **400** 字。超了直接回，不建流水。
- 输出 **`max_tokens=256`**，`temperature=0`，`response_format=json_object`，`thinking.type=disabled`（与错题摘要同一条理由：不关就会自己烧推理 token）。
- 超时 **30** 秒，`allow_redirects=False`。
- **不扣**：空、超长、没密钥、我们自己的代码在发请求前崩了、超时、网络错误、非 200。
- **扣**：HTTP 200。包括 `found:false`、JSON 不合约定、式子一条都画不了。页面上的中文会写明「这次已计入今日次数」。

## 密钥

- 只有 `base.group_system` 能看状态、能保存。别人走 `AccessError`，控制器回 **403**。
- 保存：写入 `.env`（先写临时文件，`0600`，`os.replace`；拒绝符号链接、拒绝文件名不是 `.env`），
  再 `os.environ['DEEPSEEK_API_KEY']=...`，所以当前进程不用重启。
- 返回值只有 `configured` / `masked`（`****` 加末四位）/ `source`。前端再滤一次，不像掩码的字符串不往页面上写。
- 默认路径是**模块目录**下的 `.env`。`docker-compose.yml` 只把
  `server/addons/tutoring_center` 挂进容器，仓库根的 `.env` 进程读不到。`.gitignore` 的 `.env`
  不带斜杠，两处都忽略；写入用的 `tmp-deepseek-*` 也忽略。

## 同日续：题目图片，以及大题里的方程不再被拒（19.0.1.23.0）

用户把一道椭圆题贴进输入框：

`3.椭圆 C: frac{x^{2}}{16}+frac{y^{2}}{7}=1 的两个焦点分别为 F_{1}, F_{2}，……周长为`

页面回了「画不出来（不是函数图像）」并扣了次数。根子在提示词：凡是「解题」一律 `found:false`，模型就按字面把整道题拒了。方程本身画布肯收。

- 提示词改成：材料里已经写明的曲线方程必须 `found:true`，只画那条方程，不去算周长。`prompts/plot_system.txt`、`plot_user.txt`，图片另有 `plot_user_image.txt`。
- 服务端再兜一层：`frac{x^{2}}{16}`、`\frac{x^{2}}{16}`、`x^{2}` 先收成画布写法。模型仍拒绝或 JSON 对不上时，从原文把肯画的方程捞出来再画。token 已经花了，这次照扣。原文里根本没有方程（例如「今天天气怎么样」）才继续报画不出来。
- 登录用户可以上传 jpg/png/webp/gif，最大 8MB。服务端看文件头，不认 SVG。缩成 JPEG（长边 1600，识图超时 60 秒）后走与错题摘要相同的 `image_url`。空文本加不合格图片在发请求前拒绝，不扣次数。匿名仍然只能看到登录链接。

## 同日再续：该解题时先解出函数再画（19.0.1.24.0）

上一版把「不要解题」写进了提示词，是为了拦住「椭圆方程已经给出、后面问周长」被拒。用户补充：并不是不让模型解题。有的题要用到函数图像，或者答案本身就是某个函数，必须先把题做完才知道画什么。

- 提示词分成两支。材料里已经写明的曲线：画那条，周长、面积、焦点坐标这种数不拿去画。没有现成方程，但答案是函数或曲线、或必须先求出才能画：先把题解完，再把方程放进 JSON。给出一条再求另一条（切线、对称）时两条都画。
- 回复仍然只有方程 JSON，页面不展示解题过程。输出 token 上限仍是 256。
- 页面上的说明改成同一句话，避免再写成「一律不解题」。
- `dev/zz_plot_ai_unit.py` 131 项过。提示词必须写「先把题解完」，并且不再出现「任何所求」「不要回答后面的求解问题」。一次性库 `-u tutoring_center` 0 ERROR，登录后的页面说明已是这句。

## 同日再续：一次最多 16 条方程（19.0.1.25.0）

轮胎人那种主体拆开要很多圆，原来一次只收 4 条。`MAX_CURVES` 改成 16，多出来的仍然丢掉，页面写「只绘制前 16 条」。提示词同步。输出 token 从 256 提到 2048，否则 16 条方程的 JSON 会被接口截断，整段解析失败。

`dev/zz_plot_ai_unit.py` 132 项过。一次性库 `-u tutoring_center` 0 ERROR。页面上让桩一次回 17 条直线，图例留下 16 条，状态是「已绘制 16 条。只绘制前 16 条。」

## 同日再续：连续多个 JSON 体合并后再画（19.0.1.26.0）

之前只把回复里第一对到最后一对大括号当成一个 JSON，而且请求带了 `response_format=json_object`，模型只能回一个对象。两个并排的 `{"found":true,"curves":[...]}` 会整段解析失败。

现在按出现顺序用 `raw_decode` 取出每个顶层对象或数组，方程合并后仍最多 16 条。其中一个对象拒绝、旁边还有方程，就画那些方程。请求不再锁死单个 JSON。`dev/zz_plot_ai_unit.py` 138 项过。

# 同日第二条分支：知识库条目「谁可以看」（`feature/library-item-sharing`，`19.0.1.29.0`）

> 需求（维护者原话口径）：知识库每个条目打开后可以点「谁可以看」，默认只有自己；
> 勾上的人能看到这条，但**可选的只有和这个教师相关的学生**，不是服务器里的所有人，
> 而且**不占被共享者的空间**。他当场拍板三条：候选名单只给学生的门户账号（先不加老师字段）、
> 教材**一律靠手动勾**（不做"教辅分类自动对登录用户可读"）、入口只放条目详情页。

## 做法

- 条目上加 `share_user_ids`（m2m `tutoring_library_item_share_rel`）。**配额不用改**：
  `used_bytes()` 本来就是 `SUM(file_size) WHERE user_id = 本人`，行不搬家、`user_id` 不变，
  所以对方一格都不占——这条是"免费"的，别去写什么"共享副本"。
- 新增一条**只放开 read** 的记录规则 `rule_library_item_shared_read`
  （`[('share_user_ids','in',user.id)]`，groups 同"仅本人"那条）。
  同组内规则按"或"算，而 write/create/unlink 只认带那些标志的规则，
  所以被共享的人**看得见、改不动、删不掉**（模型层断言直接 `AccessError` 验过）。
- 候选名单 = `tutoring.student` 全表的 `partner_id.user_ids`，再剔掉内部用户与条目主人自己
  （库里**没有** teacher↔student 字段，这是唯一能认的链；所以"和我相关的学生"目前＝"平台上的学生"，
  真来了第二位老师要再补 `teacher_ids`）。
- **不信任界面**：`write()` 里 `_clean_share_commands()` 把名单外的 id 一律剔掉，
  裸 id 列表 / `[(4,uid)]` / `[(6,0,ids)]` 三种写法都收敛。
- 门户：详情页主人一个 Bootstrap 原生 collapse 面板（+ `noscript` 摊开退路，零新 JS）；
  列表页多一个「共享给我」药丸（换的是归属那一维，此时不能再叠 `user_id=本人`，否则两条域互相否掉）；
  分类药丸的计数**始终数我自己那一份**，共享那条单独 `search_count`。
- 只读渲染：非本人的条目**不渲染文件夹 / 标签 / 错题关联**——那三样各自按本人或联系人隔离，
  读 `folder_id.name` 会先炸 `AccessError`，而且标签名本身就是"这个人在学什么"，
  搜得到就等于透出去；所以共享栏的搜索域也去掉了 `tag_ids.name`。
- 四个写入口（改名/保存正文/删除/补附件）的 `search` 域里补钉 `('user_id','=',user.id)`：
  read 放开之后，"能读到"不再等于"能改到"。

## 顺手挖出并纠正一条写错的注释

`security/tutoring_security.xml` 里原本写着"委托继承的字段在 SQL 里 JOIN 出来，不受本规则影响"。
**实测相反**：`biaodi`（门户）对 `tutoring.workbook.file` 的 `search_count` 是 **0**，
读 `content` 直接 `AccessError`——父表"仅本人"那条规则就是拦教材的那道墙。
这就是"门户学生读不到教材"那条老 bug 的真因（AI 摘要侧当年靠 `sudo()` 绕过去，所以一直没人发现注释是错的）。
正解就是这次的共享：把那条教材条目勾给学生，`/my/learning/workbook-files/<id>` 从 404 变 200（已验）。

## 新陷阱 66、67

**66：`t-call` 出来的子模板里没有 `user`，只有 `env.user`。** 门户卡片 `library_card` 里写
`item.user_id.id == user.id` 直接 `KeyError: 'user'` → 整页 500（服务端日志里才是 traceback，
浏览器只看到 500 页）。`portal.portal_layout` 那层会带 `user`，但被 `t-call` 的片段拿的是
自己的框架上下文，别指望父模板的变量渗进来。写片段里的"是不是我"一律 `env.user.id`。

**67：同主机不同端口共用一个 cookie jar。** 浏览器面板里 8069 已经登录过，再打开
`http://127.0.0.1:8899/web/login` 提交，会 400 `Session expired (invalid CSRF token)`——
`session_id` 是按主机存的，8899 收到的是 8069 那个进程签发的会话。
两头都要在浏览器里点时，先重新加载登录页拿 8899 自己的会话；反过来也一样：
在 8899 登录会把 8069 的会话顶掉。**这不是服务坏了**（`curl` 另开会话一切正常）。

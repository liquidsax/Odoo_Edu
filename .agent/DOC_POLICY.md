# 文档分工与仓库卫生（2026-10-16 起）

> 一句话：**开发过程记录只留在本地，仓库里只留"装得上、用得懂"的东西。**
>
> 本项目的开发者极少（基本是维护者本人加若干 agent），而 `.agent/` 里那批按日期写的
> 开发日志同时带着本机服务形态、备份文件名、一次性库名、部署流水和真实学习数据。
> 对少数接手者它们价值很高，对公开仓库它们是不成比例的暴露面。所以从这一天起分两版。

## 三、今后新东西写哪儿

| 要写的东西 | 落点 | 入库 |
|---|---|---|
| 日常交接、开发日志、部署流水、验收记录 | `.agent/local/` | 否 |
| 按日期的更新记录 | `.agent/local/updates/` | 否 |
| 一次性验收 / 冒烟 / 造数脚本 | `dev/zz_*` | 否 |
| 开发向文档（可行性评估、内部方案、测试指南） | `docs/dev/` | 否 |
| 界面截图、图素材 | 本地任意位置 | 否 |
| 安装步骤、使用说明、架构说明的修正 | 第一节那几份公开文件 | 是 |

以上"否"的路径都已写进 `.gitignore`。确实需要往仓库里放同名路径的新文件时，
先与维护者确认，再用 `git add -f`。

## 四、公开文档里不写的东西

沿用 `.agent/handoff.md` 协作规则第 5 条，并补明确：

- 账号与口令（含演示账号）、数据库凭据、API 密钥——**连"存在哪个文件"都不写**；
- 本机绝对路径、Windows 服务名、备份文件名与体积、一次性库名、端口与 `--db-filter`；
- 真实学生的姓名、分数、错题原文，以及任何能认出具体某个人的截图；
- 公网那台机器的地址、目录与口令位置（记在那台机自己的运维档案里，不在本仓库）。

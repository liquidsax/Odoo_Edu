# R3ynA 学习平台小程序化可行性评估

> 评估日期：2026-10-15　评估对象：`server/addons/tutoring_center`（R3ynA 学习平台，Odoo 19 社区版）
> 结论口径：**技术上可行，行政上是主要风险**。本文只做判断与路线设计，不动代码。

---

## 一、结论（先看这段）

1. **能做成小程序，但不是"把这个网页打包过去"**，而是另起一个客户端：小程序侧重写界面，Odoo 侧新增一层给程序调的 JSON 接口。
2. **最大的优势**：平台的全部业务规则与权限口径都写在模型层与记录规则里（错题门户只能本人读写、知识库按行级隔离、老师之间互不见私人档案、练习册共享给学生才能读）。接口层直接走 `search()` / `has_access()`，就自动继承这套口径，**不需要在小程序里重新实现一遍权限**。这是这个项目相比一般"改造上小程序"的最大不同。
3. **最大的门槛不是代码，是三道行政关卡**：小程序主体、ICP 备案域名、服务类目资质。
   - `web-view` 组件仅**非个人主体**可配业务域名（个人主体后台连入口都没有）；
   - 教育类目**禁止个人主体申请**，企业主体还要营业执照（学科类还要办学许可）；
   - 域名必须 HTTPS + ICP 备案，不支持 IP，且 **Odoo 不能挂子路径**（陷阱 18），必须给它一个独立子域名。
4. **"用体验版绕开审核"这条只对原生小程序成立，对 web-view 不成立**：个人主体小程序发体验版可以不提交审核（绕开类目与资质），但**`web-view` 连体验版真机也打不开**——个人主体后台没有"业务域名"配置入口（微信官方社区实证）。见第四节补充。
5. **如果诉求只是"手机上看得到我的学习数据"，最优解可能连小程序都不需要**：直接把门户 `/my/*` 的链接发到微信里，用微信内置浏览器打开，体验与 web-view 几乎一样，零主体、零备案、零审核。见第四节补充的路径对比。
6. **推荐第一步不是打通登录，而是把 `/tools/function-plot` 搬过去**：它纯前端、零登录、零后端依赖，用来验证"小程序 `canvas type="2d"` + 你那套数学解析器跑不跑得动"。这一步失败，后面都不用谈；这一步成功，剩下的都是体力活。

## 三、为什么网页代码搬不过去

不是工程量问题，是运行时根本不兼容：

- **没有 DOM / HTML / CSS 选择器**。小程序只有 WXML/WXSS + 原生组件，`document`、`window`、`addEventListener`、querySelector 全都不存在。Owl、Bootstrap、jQuery 一律不跑，也不能加载外部 CDN。
- **门户页是服务端渲染的 HTML 字符串**，小程序没有任何办法渲染它（除非走 `web-view`，那等于没做小程序）。
- **具体搬不动的东西**：pdf.js（教材阅读、错题"出处那一页"的封面）、`/web/content` 式流式大 PDF、鼠标悬停/滚轮/`execCommand` 那套交互模型（数学小键盘依赖 `document.execCommand("insertText")` 保撤销栈，小程序里没有这个 API，要自己实现插入与光标模型）。
- **能搬的**：`function_plot.js` 里的分词器/求值器/隐式乘法/`|x|`/`lg`/反三角（去掉 DOM 依赖即可）、复习调度口径（1→3→7→15→30→60 天）、以及**全部服务端逻辑**。

## 四、三条技术路线

### A. web-view 套壳（＝"小程序其实是个网页打开器"）

**先说清楚：这个想法是对的，而且不需要你写任何"打开器"**——腾讯把它做成了现成组件，整个小程序就是一个页面：

```html
<web-view src="https://学.你的域名.cn/my/learning" />
```

但它**不是浏览器，是白名单 webview**：

- 只能打开小程序后台配过的**业务域名**下的页面，任意 URL 打不开；域名需 HTTPS + ICP 备案，不支持 IP，且 Odoo 不能挂子路径（陷阱 18）；
- 小程序侧**拿不到网页内容**，页面内不能叠原生组件；网页只能靠 `wx.miniProgram.navigateTo` 等有限 JSSDK 能力回跳小程序，消息走单向 `postMessage`；
- 微信支付、订阅消息、自定义分享卡片这些原生能力在网页里基本用不上——**套壳之后你只得到一个壳**；
- **服务器响应头会拦它**。实测 Odoo 核心源码（`server/odoo/addons/`）对以下页面明确发了禁止被嵌的头：
  - `/web`（后台 webclient）：`X-Frame-Options: DENY`（`web/controllers/home.py:79`）→ **admin 后台绝对套不进去**；
  - `/web/login`（`home.py:152`）、`/my/account`（`portal/controllers/portal.py:196`）、`/portal/my_security`（`portal.py:886`、`935`）、注册与改密页（`auth_signup/controllers/main.py:83`、`122`）：`X-Frame-Options: SAMEORIGIN` + `Content-Security-Policy: frame-ancestors 'self'`；
  - 微信开发者工具里的 web-view 是用 iframe 实现的、真机是独立 webview，所以上面这几个头**可能表现为"工具里打不开、真机正常"（或相反）**——遇到这种怪现象先怀疑这条，别当代码 bug 去查；
- **结论：只有门户 `/my/*` 有戏，后台没戏。**

- 优点：服务端与前端**零改动**。
- 硬约束（见第五节闸门）：**非个人主体** + 已备案 HTTPS 域名 + 根目录放微信校验文件 + 不能用 IP + 不能用子路径。
- 代价：仅得"壳"；若要上架，纯套壳页面容易被判"无实质功能 / 服务类目与内容不符"驳回（自用不提交审核则无此问题）。

### A′. 到达同一个目标的三种方式（这一节回答"到底要不要小程序"）

如果真实诉求是"**手机上能打开我的学习数据**"，三条路的门槛差得很远：

| 路径 | 要办什么 | 得到什么 | 门槛 |
|---|---|---|---|
| **微信里直开 H5**（`/my/*` 现有门户页） | 一个能公网访问的域名即可；**不需要主体、不需要审核** | 体验与 web-view 几乎一样 | **最低，今天就能做** |
| **小程序 + web-view 套壳** | 个体户执照（个体户也属非个人主体，可配业务域名，认证约 300 元/年）→ 注册非个人主体小程序 → 域名 ICP 备案 → 配业务域名 | 微信"我的小程序"里的固定入口 + 分享卡片 + 订阅消息提醒；页面内容仍是那套网页 | 中（行政周期为主） |
| **原生小程序 + 开接口** | 主体 + 备案 + 12~15 个页面重写 | 真原生体验：拍照直传、推送、离线 | 高 |

**判断**：小程序壳换来的只有那三样（固定入口、分享卡片、消息提醒），而成本是执照 + 备案 + 主体认证。**如果这三样不是刚需，A′ 第一行就是答案**；如果是刚需（例如要给家人一个"点开就用"的入口），走第二行，且**服务端可以一行不改**。


### B. 原生小程序 + Odoo 开 JSON 接口（真正的"原生"）
小程序自己写页面，Odoo 侧新增 `controllers/api.py`。

- 优点：能力最全（原生分享卡片、订阅消息提醒"该复习了"、拍照直传、离线缓存）；权限口径自动继承。
- 代价：门户那 39 条路由对应的界面要重写；接口层要新写约 20 个端点。

### C. 云函数中转
小程序 → `wx.cloud.callFunction` → 云函数 → Odoo（HTTP）。

- 优点：**云开发调用不走小程序服务器域名白名单**，即小程序侧不需要备案域名，只要云函数能访问到 Odoo。
- 代价：多一跳运维与延迟；Odoo 仍需被云函数访问到（公网 IP / 端口映射 / 内网穿透），安全性要额外加固。
- 定位：**绕过备案的现实解法**，常与 B 组合使用（前端原生 + 传输走云函数）。

## 五、行政门槛（真正的拦路虎，先过这道再看代码）

| 关卡 | 要求 | 本项目现状 |
|---|---|---|
| 主体 | `web-view` 仅**非个人主体**可配业务域名；教育类目个人主体禁止申请 | 个人学习平台，无营业执照 |
| 域名 | HTTPS + ICP 备案，新备案 24h 后才可配；不支持 IP；Odoo 必须独立子域名 | 本机 `:8069` 局域网；云机存在但 34.x 未部署 |
| 类目 | "教育"需资质（营业执照；学科类需办学许可） | 无 |
| 未成年人数据 | K12 内容/功能需家长监护入口、青少年模式，是审核重点 | 平台存有真实学生数据 |

**捷径一：体验版**（只对"原生小程序"成立）——个人主体可注册，发体验版给白名单成员扫码使用，**不提交审核**，因此不需要类目与资质。**但这条绕不过 `web-view`**：个人主体后台没有"业务域名"入口，体验版真机照样打不开网页（微信官方社区实证）。

**捷径二：个体工商户执照**（要 `web-view` 时成本最低的解法）——个体户属于**非个人主体**，可配业务域名、可做小程序认证（约 300 元/年，个体户无需对公账户），比注册公司轻得多。也就是说闸门一不是死局，只是要走一趟工商流程。

**捷径三：干脆不用小程序**——见第四节 A′，微信里直开 H5 不需要任何主体与备案。

**结论**：走审核上架 → 先解决主体与资质，否则免谈；**自用且要原生小程序 → 体验版**；**自用且只要 web-view 壳 → 先办个体户执照 + 备案域名**；**只是想在手机上看数据 → 直开 H5**。

## 六、建议路线（四步，宁可小步验证）

### 步 0 · 探路（≈1–2 天）
把 `/tools/function-plot` 搬成小程序页：**纯前端、零登录、零后端**。
交付物：一个能画椭圆/双曲线/三角函数、能拖参数滑块的小程序页；用来验证小程序 `canvas 2d` 与触摸事件下，你那套解析器与绘图代码能不能复用。
判定标准：解析器原样搬过来（只去掉 DOM 调用）；缩放改成双指捏合 + 双指拖动。

### 步 1 · 只读打通（≈3–5 天）
新增 `controllers/api.py`（照 `time_sync.py` 的模式），小程序实现登录 + 只读页面。
页面：学习看板、课次列表/详情、考试成绩、错题列表/详情（只读）。
这一步的意义是把"登录 + 传输 + 权限"这条链路验穿，**不改任何模型**。

### 步 2 · 读写闭环（≈4–6 天）
错题速记条 + **拍照记题**（`wx.chooseMedia` + `wx.uploadFile` 直传，正好接你已有的"图落进知识库错题分类并各自绑回"口径），加难度、错因、知识点挑选，以及"该翻出来的队列"（复用 `_due_domain(now)` 口径）。
这是移动端最值得做的功能——**拍照记题比在电脑上点更自然**。

### 步 3 · 时间账本（≈2–3 天）
`/tutoring/time/*` 三条接口现成，小程序做手机端查看：概览四卡、任务卡片墙、同步流水。
加分项：订阅消息做"定时提醒"（移动端独有的价值）。

## 七、Odoo 侧要新增什么（接口层设计草案）

**直接照抄 `/tutoring/time/*` 已经验证过的三条模式**（`controllers/time_sync.py` 文件头注释里写得很清楚）：

1. 一律返回 JSON + 明确 HTTP 状态码，**绝不 302 到登录页**（否则客户端会把登录页 HTML 当结果解析）；
2. 用 `auth='public'` + 自己判空会话，把 401 握在自己手里；
3. `csrf=False` + 要求自定义头（如 `X-R3ynA-Client`）——浏览器发跨站请求加不了自定义头，效果与 CSRF 令牌等效；
4. 数据库名由服务端自己解析，不逼客户端填 `OdooForDB`。

**认证选型**（落地时定）：(a) 自建 token 表（可控、可吊销、可带设备维度，与 `tutoring.time.device` 一个思路）；(b) Odoo 内置 API Key（零新模型，但粒度粗）。倾向 (a)。

**接口清单草案**（约 20 个，对应 39 条门户路由里的移动端必需子集）：

- 认证：`POST /r3yna/api/login`
- 读：`/me`、`/students`、`/dashboard`、`/sessions`、`/sessions/<id>`、`/exams`、`/exams/<id>`、`/mistakes`、`/mistakes/<id>`、`/workbooks`、`/library`、`/time/summary`
- 写：`POST /mistakes/new`、`/mistakes/<id>/note`、`/mistakes/<id>/archive|unarchive|snooze`、`/mistakes/photos`（multipart 上传）、`/mistakes/<id>/attach`
- 原样复用：`/tutoring/time/ping` `/login` `/sync`

**权限纪律**：一律 `search()` / `has_access()` 取数，**不要** `browse().exists()` 再自己判 `user_id`（陷阱 26：`browse().exists()` 与缓存值不经过记录规则，会把共享进来的人重新挡在门外）。
**不做后台教师端**（`admin` 后台是给电脑的，不在小程序范围）。

### 实测：已上线（2026-10-16，云机部署后逐条验过）

按上面的草案实现为 `controllers/api.py`（版本 `19.0.1.36.0`，9 个端点，全部 GET + `readonly`），
云机部署后从本机探测的结果：

| 探测 | 结果 | 说明 |
|---|---|---|
| `GET /r3yna/api/ping`（不带客户端头） | **400** `{"ok":false,"error":"missing_client_header"}` | 客户端头这道闸生效 |
| `GET /r3yna/api/ping`（带 `X-R3ynA-Client`） | **200** `{"ok":true,"protocol":1,"service":"r3yna-edu"}` | 部署生效、协议号对得上 |
| `GET /r3yna/api/me`（无 Key） | **401** `User not authenticated, use an API Key with a Bearer Authorization header.` | **不是 302**——核心的 bearer 认证替我们守住了"绝不 302" |
| `GET /r3yna/api/me`（假 Key） | **401** `Invalid apikey` | 核心校验阶段就拦住，没进业务代码 |
| `GET /tutoring/time/ping`（Do1ng 那条） | **200** | 老接口无回归 |

**一个必须知道的瑕疵**：401 的**响应体是 HTML**（Werkzeug 默认错误页），不是 JSON——
未认证是核心在业务代码之前抛的，走的是核心错误页渲染。**客户端要按状态码分支**，
不要去解析 401 的响应体（这本来就是必须的：网关或反代也可能返回 HTML 的 502/504）。
若以后要统一成 JSON，得覆盖 `ir.http` 的错误处理，为一个"响应体长什么样"动核心不划算。

### 这层 API 到底解决什么问题

一句话：**网页是给人看的（HTML），API 是给程序读的（JSON）。** 小程序是程序、不是浏览器——
门户那 2586 行 QWeb 模板它一条都渲染不了。所以：

- 没有这层 API，小程序**只剩 web-view 套壳一条路**，而个人主体配不了业务域名 → 死路；
- 有了它，小程序可以直接取数据、自己画界面，而且**权限、筛选口径、复习调度全部复用服务端**——
  "小程序里看到的"和"网页上看到的"天生一致，因为它们是同一份实现算出来的。
- 它的用途也不止小程序：定时任务/报表、将来的其它客户端（Do1ng 那三条是同一思路的先例）、
  以及**演示**——面试时用 curl 或 Postman 展示"后端有正经的 API 层"，比翻网页截图有说服力。

**当前边界**：9 个端点全部只读。写操作（记错题、归档、拍照上传）还没做——那批要单独设计
（幂等、重复提交、错误码），不在这批范围内。

## 八、明确不做的

- 教材 PDF 在线阅读（pdf.js 搬不动，最多 `wx.openDocument`）
- Markdown 就地编辑 / 代码编辑器（桌面场景）
- 后台教师端（学生看板、Kanban、速记向导、图表页签）
- 「错题试用版本」五版并存的实验（`?lab=wall|queue|grid|daily|feed`）——小程序只落**结论版**，不再做五版
- 点赞、背景音乐（早就否掉的语义）

## 九、风险与未验证项

1. **`canvas 2d` 兼容性未验证**：`function_plot.js` 的绘制层依赖 DOM canvas 与鼠标事件，小程序 canvas 2d API 相近但不完全相同（缩放/平移手势、虚线、文字度量）。**步 0 就是为了把这条验掉**，在验之前不要承诺工期。
2. **连接可达性**：小程序真机连不上 `http://192.168.x.x:8069`（开发者工具里可勾"不校验合法域名"，真机预览受限）。要么有备案域名（路线 B），要么走云函数（路线 C）。另外云机目前**34.x 一次都没部署**，接口层要连的是哪台实例，是个需要先定的事。
3. **行政周期不可控**：备案、主体认证都是外部依赖，不并入开发工期。
4. **未成年人数据合规**：平台存有真实学生数据（含未成年人），若要公开上架，家长监护/青少年模式是审核重点；自用体验版无此要求。
5. **接口层是新攻击面**：`csrf=False` + 自定义头这套是给程序调的，必须限定在 `/r3yna/api/*` 下，且逐条走 ACL 与记录规则，不可 `sudo()` 硬闯。
6. **web-view 与 `frame-ancestors` 的相容性未实测**：Odoo 核心给 `/web`（`DENY`）与登录/账户/安全/注册页（`SAMEORIGIN` + `frame-ancestors 'self'`，行号见第四节 A）都发了禁嵌头。真机 web-view 是独立 webview、理论上不受这些头约束，但**开发者工具用 iframe 实现、行为可能相反**。套壳方案落地前必须做一次"工具 + 真机"双向实测，否则会长期误判成代码问题。
7. **微信审核对"纯 web-view 套壳"的态度**：上架（非体验版）时纯套壳页有被判"无实质功能 / 类目与内容不符"驳回的风险；自用不提交审核则无此问题。

---

## 十、一句话回答

**"小程序里能不能写个网页打开器"——能，那就是现成的 `web-view`，一行代码。但它不是浏览器，是白名单 webview：只能开你配过的备案域名下的页面，且只有非个人主体能配（个人主体连体验版都打不开）。**

- 想立刻在手机上看到学习数据 → **不用小程序，把 `/my/*` 链接发到微信里直开**，今天就能做；
- 想要"点开就用"的固定入口、又要服务端一行不改 → **办个体户执照 + 备案一个子域名 + 小程序套 `web-view`**；
- 想要真原生体验（拍照直传、推送、离线）→ 走路线 B，界面全重写（2586 行 QWeb 一行用不上），第一步先拿函数图像页探路。

真正的卡点自始至终是主体与备案，不是代码。

## 附：换个对象——个人博客站点能不能做小程序

**能，而且比本项目的学习平台容易得多。但路径要换：不做 `web-view` 套壳，做原生内容页。**

### 为什么博客不必套壳

- 博客只有"文章列表 + 文章详情"两类页面，不涉及登录、权限、行级隔离、学生数据，重写成本极低；
- 个人主体有一条正对的类目：**「资讯」下含"个人博客、文章阅读"**（个人主体可注册，登记免费，不需要 300 元企业认证费，也不要求营业执照）；
- 反观 `web-view`：要非个人主体（个体户执照）+ 域名 ICP 备案 + 站点能挂根路径。为省两个页面办这一套，不划算。

### 两条路对照

| | 原生内容页（推荐） | web-view 套壳 |
|---|---|---|
| 主体 | 个人主体即可，类目「资讯」 | 非个人主体（个体户执照） |
| 域名 | 不需要（内容走云开发） | 必须备案 HTTPS + 能挂根路径 |
| 页面 | 列表 + 详情 | 一个 `web-view`，服务端零改动 |
| 内容 | Markdown → 富文本节点 | 原网页 |
| 收益 | 分享卡片、微信内固定入口 | 只得到一个壳 |

### 博客特有的坑（都会真遇到）

1. **站点在境外就基本没戏**：Vercel / GitHub Pages / Cloudflare Pages / 境外 VPS 上的博客无法 ICP 备案 → 既不能配业务域名，也进不了小程序的**服务器域名白名单**。要么把站点搬回大陆服务器，要么走**云开发**（`wx.cloud` 不走域名白名单）。
2. **小程序自身也要 ICP 备案**（注意：这是小程序备案，不是域名备案）：个人主体办得了，需身份证 + 人脸核验，走工信部系统，**上架前必须完成**。
3. **富文本会掉格式**：小程序 `<rich-text>` 只认有限标签，`class`、大部分 `style`、自定义标签都不支持，**代码块高亮必掉**。解法是提前把 Markdown 渲染成 `<rich-text>` 的节点树，而不是把博客 HTML 原样塞进去。
4. **图片受同样的域名约束**：未备案域名的外链图片加载不出来 → 图片放**云存储**。
5. **内容审核**：内容型小程序审核会看内容；个人主体**不能做经营性变现**（挂广告、收费阅读、付费专栏都不行）。
6. **发文即发版**：内容打包进小程序包的话，每发一篇文章都要重新提审（1–7 天）。要免掉就走云开发数据库或自己的 JSON 接口。

### 什么情况下才值得做

**唯一的硬理由是"分享"**：文章能变成一张带标题和封面的分享卡片发给朋友/群，比自己博客的长链接体面得多，另外还有微信搜索里的自然流量、可与公众号关联。如果不需要分享卡片，**把链接发到微信里直开就够了**，零成本零审核。

## 十一、体积限制与发布口径（2026-10-16 实测校准）

### 体积：官方口径 + 本项目实测

| 项 | 口径 |
|---|---|
| 单个分包 / 主包 | **≤ 2MB**（压缩后体积） |
| 全部包合计 | **≤ 30MB**（服务商代开发的账号 20MB） |
| 主包必须放 | 启动页、tabBar 页、所有分包共用的 JS 与资源 |

**本项目实测**（`server/addons/tutoring_center`，去掉 `__pycache__`）：

- 全部代码 **0.9MB / 93 个文件**；
- 最大单文件是 **178KB 的 `views/portal_templates.xml`**——那是 QWeb 模板，小程序根本不用它；
- 前端 JS/CSS 合计 **约 0.2MB**（其中 `function_plot.js` 129KB 是最大一件）。

**结论：2MB 主包对"代码"毫无压力。** 真正吃体积的永远是静态资源（图片/字体/大 JSON），而本项目最大的资源——教材 PDF（《53》拆 3 份，单份接近 96MB 上传上限）——**存在 PostgreSQL 的 `bytea` 列里，是服务端资源，永远不进代码包**。

唯一要立规矩的地方：若将来想把服务端渲染出来的图（如错题封面）放进包里做离线兜底，必须按 2MB 主包做预算；否则一律走网络或云存储。

### 发布口径（三条修正）

1. **个人主体可以发布上线**，不是"不能发布"。官方成员表：个人主体可绑 **15 个项目成员 + 15 个体验成员**。
2. **卡的是类目**：教育类目个人主体不可选；改选"工具"又构成"类目与实际功能不符"，同样驳回。**这才是死结**，不是"个人不能发布"。
3. **体验版是自用的正解**：体验版**没有时间限制**（"14 天作废"说的是"试用小程序"，是另一种东西），个人主体可加 15 个体验成员，成员扫码即用，**不提交审核、不需要类目**。两个注意点：体验版二维码有效期约 **7 天**（过期重新生成即可）；**一个小程序只能有一个体验版**，重新上传代码后要回后台**重新设为体验版**，不会自动更新。

## 十二、以"证明开发能力"为目标的展示方案

目标是展示而不是运营，取舍就完全不同：**要让面试官在你不在场时，扫码就能看到东西。**

**前提问题（2026-10-16 实测更新：这个前提已经不存在了）**

原以为后端只在局域网 `:8069`、面试官的手机连不上。实测云机后推翻：

| 项 | 实测结果 |
|---|---|
| 云机 | `tx` 119.91.140.197，2 核 / 3.3G（无 swap）/ 59G 已用 49%，load 0.17 |
| Odoo | 容器 `odoo_edu-odoo-1`（镜像 `odoo:19`）**正在运行**，`Odoo Server 19.0-20260926`，业务库 `edu_prod` |
| 模块版本 | 云端 `tutoring_center` **19.0.1.35.0**，**与本机开发树完全一致**（handoff 里"云机一次都没部署"已过时） |
| 备案 | `r3yna.site` **已备案**。判据：80 端口返回我们自己 nginx 的 `301→https`，而不是腾讯云边缘注入的 `302 → dnspod` 拦截页 |
| 独立子域名 | `edu.r3yna.site` 已解析到同一 IP，nginx `proxy_pass http://edu_odoo`，并单独代理 `127.0.0.1:8072`（长轮询端口）——正好满足"Odoo 必须独立子域名、不能挂子路径"这条（陷阱 18） |
| HTTPS | 证书 `CN=r3yna.site`（TrustAsia DV），**有效期至 2027-01-01**；本机探测 `https://edu.r3yna.site/` 返回 200，系统信任链校验通过 |

**结论：方案 B/C 的基础设施已经全部就位，剩下两件小事：**

1. **给模块加一层给小程序调的 JSON 接口**（`controllers/api.py`，照 `time_sync.py` 那四条纪律），本机开发后部署到云机；
2. **在小程序后台把 `https://edu.r3yna.site` 配进"服务器域名"**——个人主体可配，不需要企业主体、不需要 web-view。

**两个待确认点**：① 后台配域名时才会知道备案主体是否要求与小程序主体一致（不一致的话用个人名义另备一个域名即可）；② 小程序连的是云机的 `edu_prod` 库，与本地 `OdooForDB` 是两个库，展示时数据来自云机。云机 2 核 3.3G 无 swap，接口层别做重活。

**方案 A（演示模式）降级为可选**：真后端已公网可达，扫码就能连真数据，比 mock 更有说服力。只有在"云机挂了/家里网断了"这种兜底场景才需要它。

**展示清单（按"最能说明能力"排序）**：

1. **函数图像工具**——`function_plot.js` 129KB 纯前端、零后端依赖，含自写数学解析器 + canvas 绘图 + 参数滑块。**这是搬过去后最能打的一个单品，也是最好的探路步。**
2. 错题卡片墙 + 分组/筛选/下钻——能讲的点：服务端 `domain` + `limit/offset` 取数、`read_group` 统计、复习调度口径。
3. 拍照记题——`wx.chooseMedia` + `wx.uploadFile` 直传。
4. 时间账本——三条机器接口现成。

**演示版的取舍**：保留**界面与交互全流程**，把真实数据换成样例；砍掉教材 PDF 在线阅读与后台教师端。

**面试时最值钱的三句话**（比功能列表有说服力）：

- "权限口径没有在小程序里重写一遍——它写在服务端的记录规则里，客户端只拿得到自己那些行。"
- "调度这类逻辑我抽成纯函数做了单测：连续 400 天天差逐日 +1，2 月 29 日在平年顺延。"

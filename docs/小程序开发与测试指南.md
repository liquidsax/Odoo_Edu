## 零、先分清三套环境（决定你每一步能不能连通）

这是整个小程序开发里最容易栽的地方——**"工具里好好的，真机白屏"基本都是这张表没分清**。

| 环境 | 域名校验 | 协议 | 能连内网 IP / 本地服务 | 怎么放宽 |
|---|---|---|---|---|
| **开发版**（开发者工具模拟器） | 可手动关闭 | HTTP 也行 | **能**（`http://192.168.x.x:8069` 可以） | 详情 → 本地设置 → 勾「不校验合法域名、web-view(业务域名)、TLS 版本以及 HTTPS 证书」 |
| **预览版 / 体验版**（真机） | 默认**开** | 默认仅 HTTPS | 默认不行 | 真机上打开小程序 → 右上角「…」→ **开发调试** → 打开调试；**必须手机与电脑同一 WiFi** |
| **正式版** | **强制** | 仅 HTTPS + TLS 1.2+ | 不行 | 无。必须备案域名 + 后台白名单 |

其他硬口径：服务器域名**不支持 IP、不支持带端口号、不支持通配符**；后台每个类型域名有数量上限（口径随规则变动，以后台为准）；**域名配置改动约 10 分钟才生效**——改完立刻测不通属正常。

**本项目的联调姿势**：
- 日常写代码 → 第 1 层（工具 + 勾不校验 + 局域网 IP），零成本；
- 要看真机手感 → 第 2、3 层（真机调试 / 预览码 + 手机上开调试）；
- 想给家人长期用且不想备案域名 → **云开发中转**（`wx.cloud.callFunction` 不受服务器域名白名单约束），这是最省心的一条；
- 想上架正式版 → 备案 HTTPS 域名，那是另一个阶段的事。

## 一、准备工作（一次性）

1. **注册个人主体小程序**：`mp.weixin.qq.com` → 小程序 → 邮箱注册 → 主体类型选「个人」→ 身份证实名 + 微信扫码绑定管理员。个人主体**登记免费**，不需要 300 元/年的企业认证费，也不需要营业执照。
2. **记下 AppID**：后台 → 开发 → 开发管理 → 开发设置。（AppID 不是密钥，可以进仓库；**AppSecret 绝不能进仓库**。）
3. **装微信开发者工具**（Windows 版，官网下载），用管理员本人的微信登录。
4. **打开服务端口**：工具里 → 设置 → 安全设置 → 开启「服务端口」（含 HTTP 调试、自动化测试）。**不要求用 CLI 和自动化测试时必踩这个坑。**
5. **类目**：本项目属教育类，**个人主体无法选**。自用走体验版不需要审核、也不需要纠结类目；真要走审核，先解决主体（见评估文档第五节）。
6. **可选但推荐**：开通云开发（拿 `env id`），真机联调最稳的一条路。

## 三、后端：Odoo 侧新增接口层

**直接照 `controllers/time_sync.py` 已经验证过的四条纪律**（那个文件头的注释写得很清楚，是给 Do1ng 桌面端踩出来的）：

1. 一律返回 JSON + 明确状态码，**绝不 302 到登录页**（否则客户端会把登录页 HTML 当结果解析）；
2. 用 `auth='public'` + 自己判空会话，**401 握在自己手里**；
3. `csrf=False`，改用自定义头（如 `X-R3ynA-Client`）当令牌——浏览器发跨站请求加不了自定义头，效果等同 CSRF 令牌；
4. 库名由服务端自解析，不逼客户端填 `OdooForDB`。

**认证不要靠 cookie**：小程序的 `wx.request` 对 cookie 的维护不可靠，登录成功后**签发一个 token**，客户端存 storage、后续请求带 `X-R3ynA-Token`（可以照 `tutoring.time.device` 的思路建一张 token 小表：user_id / token / device / 有效期）。

**补充一条小程序独有的好处**：`wx.request` 不是浏览器，**没有同源策略、不会有 CORS 预检**，所以你不需要给 Odoo 加任何 CORS 头；自定义头在这里纯粹是"防浏览器跨站"用。

最小骨架（新增 `server/addons/tutoring_center/controllers/api.py`）：

```python
from odoo import http
from odoo.http import request

CLIENT_HEADER = 'X-R3ynA-Client'
TOKEN_HEADER = 'X-R3ynA-Token'


def _json(status, payload):
    return request.make_json_response(payload, status=status)


def _error(status, code, msg):
    return _json(status, {'ok': False, 'error': code, 'message': msg})


def _current_user():
    """按 token 取用户；取不到返回 None（路由自己回 401，不 302）。"""
    token = (request.httprequest.headers.get(TOKEN_HEADER) or '').strip()
    if not token:
        return None
    # TODO: 查 token 表，返回 user；这里留成接口，实现时替换
    return None


class TutoringApiController(http.Controller):

    @http.route('/r3yna/api/login', type='http', auth='none',
                methods=['POST'], csrf=False, readonly=False)
    def api_login(self, **kw):
        if not (request.httprequest.headers.get(CLIENT_HEADER) or '').strip():
            return _error(400, 'missing_client_header', '缺少客户端标识头。')
        # 解析 JSON → 校验账号密码 → 签发 token（照 time_sync.time_login 的写法）
        ...

    @http.route('/r3yna/api/mistakes', type='http', auth='public',
                methods=['GET'], csrf=False)
    def api_mistakes(self, **kw):
        user = _current_user()
        if not user:
            return _error(401, 'unauthorized', '未登录或登录已过期。')
        # 关键：一律走 search()/has_access()，不要 browse().exists() 再自己判 user_id
        # （陷阱 26：browse().exists() 与缓存值不经过记录规则）
        recs = request.env['tutoring.mistake'].with_user(user).search(
            [], limit=20, order='next_review_at asc nulls first')
        return _json(200, {'ok': True, 'items': [
            {'id': r.id, 'difficulty': r.difficulty, 'note': r.note or ''} for r in recs
        ]})
```

**别忘了本项目的硬规矩**：改了 Python 必须停服升级才生效——
`svcctl.ps1 stop odoo` → `python odoo-bin -c odoo.conf -d OdooForDB -u tutoring_center --stop-after-init` → `start odoo`。

## 四、小程序侧：请求封装

`config.js`：

```js
// 开发期指向本机局域网地址（手机与电脑同一 WiFi），正式期换成备案 https 域名
const ENV = 'dev'

```

`utils/request.js` 要点（不贴全文）：返回 Promise；自动带 `X-R3ynA-Client` 与 `X-R3ynA-Token`；`statusCode === 401` 时清 token 并跳登录页；超时 10 秒；失败统一 `wx.showToast`，**把服务端返回的 message 原样透出**（否则联调时你只能看到"请求失败"）。

图片上传：`wx.uploadFile`，注意 **header 里也要带 token**，且 `uploadFile` 的合法域名是**单独一栏**配置的（很多人只配了 request，上传就 fail）。

## 六、测试：五层递进，每层都要过

### 第 1 层 · 开发者工具模拟器（90% 的时间在这）
勾上「不校验合法域名…」，`baseUrl` 指向本机局域网 IP，直接联调。
**能验**：接口通不通、数据结构、页面逻辑、登录态。
**验不了**：真机手势（缩放/滑动）、真实机型样式、真机网络策略。

### 第 2 层 · 工具内「真机调试」
工具上方「真机调试」→ 手机扫码 → 手机上出现**调试面板**（vConsole），console 与网络请求同步回工具。
**能验**：真机上的报错、请求失败原因。
**注意**：真机仍受域名校验，连内网 IP 需要在手机端把调试打开。

### 第 3 层 · 预览二维码
工具「预览」生成二维码，扫码即用，**不占用版本号**。
**能验**：真机样式与手势；发给别人看效果。
**注意**：同样受域名校验；且预览码有时效。

### 第 4 层 · 上传 → 体验版（你的终点：邀请制使用）

这是"不进应用商店、只给被邀请的人用"的标准做法，正好符合本项目"证明能力、邀请制演示"的目标：

1. 工具「上传」代码 → 后台「版本管理」里出现一个**开发版本**；
2. 点「选为体验版」——**不提交审核**，因此不需要类目、不需要资质、不需要主体升级；
3. 「成员管理 → 体验成员」把对方的微信号加进去——**个人主体上限 15 个体验成员**（项目成员同为 15）；
4. 后台生成体验版小程序码发给对方，**对方扫码即用**。

四个必须知道的口径：

- **体验版没有时间限制**（网上"14 天作废"说的是"试用小程序"，是另一种东西）；但**体验版二维码有效期约 7 天**，过期重新生成即可；
- **一个小程序只能有一个体验版**：重新上传代码后要回后台**重新设为体验版**，它不会自动更新；
- **没被加进体验成员的人，拿到码也打不开**——这正是"邀请制"的效果；
- 前提是**对方手机能访问到你的后端**：本项目用已备案的 `https://edu.r3yna.site`，所以云机必须在跑。

> 小程序自身的 ICP 备案通常与"发布上线"环节挂钩；不发布、只用体验版，一般不会被要求。后台若提示备案，按引导做即可（个人主体能办）。

### 第 5 层 · 提交审核 → 正式版
到这一步才必须：备案 HTTPS 域名（且能被小程序后台配进白名单）+ 完成**小程序自身的 ICP 备案** + 类目资质。本项目个人主体做不到教育类目，需换主体。

## 八、故障对照表（照着查，别瞎试）

| 症状 | 真因 | 处置 |
|---|---|---|
| 工具里 request fail | 没勾「不校验合法域名」/ 地址写错 | 勾开关；确认本机 Odoo 在监听、手机电脑同网段 |

| 工具正常、真机异常（且是接口没问题） | 证书链不完整 / TLS 版本过低 | `openssl s_client -connect 域名:443 -showcerts` 查链路 |
| 后端改了不生效 | 本机要停服升级 | `svcctl.ps1 stop odoo` → `-u tutoring_center --stop-after-init` → `start odoo` |
| 中文注释脚本报 UnicodeError | 控制台代码页 | 跑脚本加 `PYTHONUTF8=1` |

## 九、纪律

1. **一层验过再上一层**：模拟器 → 真机调试 → 预览 → 体验版；不要攒到最后一起测（这条与项目 `MULTI_AGENT.md` 的口径一致）。

## 附二、新增接口层对现有项目的影响（改动清单与回滚）

### 改动清单：**2 个文件 + 版本号一行**

| 动作 | 文件 | 说明 |
|---|---|---|
| **新增** | `controllers/api.py` | 纯新增，不碰任何既有文件 |
| **修改** | `controllers/__init__.py` | **加一行** `from . import api` |
| **修改** | `__manifest__.py` | 只改 `version` 字段（按版本号规矩占一个新号，如 `19.0.1.36.0`） |

**完全不动的东西**：模型与数据库结构（**不新增模型、不新增 ACL、不写迁移脚本**）、现有 48 条路由、门户页面、后台视图与资产包、Do1ng 的三条同步接口、记录规则与隐私口径（全部复用，一条都不重写）。

### 一个让方案更轻的发现：核心自带 `auth='bearer'`

Odoo 19 **核心实现**里已经有这条路：

- `odoo/http.py:777` — `auth='bearer'`："The user is authenticated using an 'Authorization' request header, using the Bearer scheme with an API token"，且默认 `save_session=False`（无状态）；
- `odoo/addons/base/models/ir_http.py:212` `_auth_method_bearer()` — 从 `Authorization: Bearer <key>` 取值，走 `res.users.apikeys._check_credentials(scope='rpc', key=token)`；**失败抛 `Unauthorized`（401 + `WWW-Authenticate: bearer`），不是 302 到登录页**；没带 key 时同样 401。

这正好是我原本要自己实现的那条"绝不 302"纪律，而且是核心实现的。**所以连 token 表都不用建**：

- API Key 由用户在 Odoo 网页端「偏好设置 → 账户安全 → 新建 API Key」自己生成、自己吊销（核心自带 UI，还能设有效期）；
- 小程序把它存 storage，后续请求带 `Authorization: Bearer <key>`；
- 权限照旧：核心已把 `request.env` 切到该 key 的所属用户，后面走 `search()` 就自动继承记录规则。
- 注意：生成 key 时 **`scope` 要留空**（核心注释写明 `'rpc' scope does not really exist, we basically require a global key`）。

### 需要留意的四件事

1. **新增一个对外入口** `/r3yna/api/*`。缓解：`auth='bearer'` 让核心在业务代码之前就拦掉无 key 请求；再加自定义头；只读接口起步；逐条走 `search()` / `has_access()`。
2. **必须停服升级**（Python 变更）：`svcctl.ps1 stop odoo` → 跑 `-u tutoring_center --stop-after-init` → `start odoo`，期间门户短暂不可用（几十秒到几分钟）。这是既有规矩，不是新增风险。
3. **写接口只影响"被调用那台机"的库**：本机升级不会动云机的 `edu_prod`；云机部署后，小程序写的是云机那一份数据。两套库本来就隔离。
4. **云机 2 核 / 3.3G / 无 swap**：接口层不要做重活（别在请求里跑 AI、生成图片、抽 PDF 页），那些留在 `ir.cron` 里做。

### 回滚
